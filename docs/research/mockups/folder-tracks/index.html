B · One folder at a time

A file browser: the card shows one folder's children, a folder row opens it, a breadcrumb and a back button go up. Nothing is indented, so depth costs no width. The price is that the narrator never sees the whole project at once.

C · Grouped flat list

No collapsing. Each folder becomes a sticky group header carrying its path and count, and its tracks sit under it at one fixed indent. The smallest change from today, and it reads well in a long list. It flattens a folder inside a folder into a path string, so the shape of the project is lost.

Recommendation

Build A, and give the Chapter links picker the same tree. It is the only layout where the narrator sees the project the way REAPER shows it, keeps the table they know, and can fold away a 40-track Retakes folder. B hides the project's shape and costs a click per level. C is the cheapest but cannot show a folder inside a folder, so a deep project reads wrong.

Decisions for the owner

  1. Layout. A (recommended), B or C. The picker is the tree under A and B, and a flat list with the path under each name under C.
  2. Can a folder be a link target? Recommended: yes when it has audio of its own, shown but disabled (with a tooltip) when it has none. The alternative is leaf tracks only, which would refuse a narrator who recorded straight onto a folder.
  3. Where do the folders start? Recommended: all open up to 30 tracks; above that, closed except the path to every linked track. Alternatives: always closed, or follow REAPER's own collapse flag. The open and closed state is not saved.
  4. The wire change. Real depth needs the host to send it: depth and isFolder on each track (additive, no hostAPIVersion bump). Approve it as its own slice before the build; the README lists the steps.
