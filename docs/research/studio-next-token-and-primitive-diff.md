# Studio Next token and primitive diff

**Status (2026-10-11):** evidence for [Studio Next Foundations](../prds/studio-next-foundations.prd.md) slice SNF-1. It changes no code. SNF-2 (the token batch) reads the tables below and edits `apps/ui/src/styles.css`; SNF-5a to 5c read the primitive table.

**Method.** The mock side is read from `docs/research/mockups/studio-next/src/styles/app.css` (`:root`, the `prefers-color-scheme` block and `:root[data-theme="dark"]`, lines 2 to 23), with the later rules of the same file applied as the cascade does. The repo side is the `:root` and `:root[data-theme='dark']` blocks of `apps/ui/src/styles.css`. The tables were generated by comparing the two files, not typed by hand; nothing was rendered in a browser and no contrast was computed (SNF-2 adds the `PAIRS` rows). A repo value that aliases another token is shown resolved, with the alias named.

**Scope of the ruling.** The Studio Next mock is the only spec for every page it covers (A1, [ADR 0760](../adr/0760-the-studio-next-mock-is-the-only-spec-for-every-page-it-covers-tokens-primitive-sizes-and-layouts-included.md)). The mock wins where it differs from the repo, so "Differs" below is the list of values SNF-2 replaces. A token that no mock rule uses is not added ([PRD Phase 2](../prds/studio-next-foundations.prd.md)).

## 1. Colour and shadow tokens

The pairing in the second column is by role, as the mock's own rules use the token. The mock's six hues (copper, ok, warn, bad, info, violet) each come with a `-soft` fill; the mock's pages colour speakers, entity kinds and marks from them through `var(--<colour>)` built at run time (`src/selectors/speakers.ts`, `src/selectors/bible.ts`, `src/pages/script/Para.tsx`), so all six families count as used by a page.

"Differs" says in which theme the mock's value is not the repo's (`both`, `light`, `dark`, `no`) or that the repo has no token (`missing`). Hex case and `#fff` against `#FFFFFF` are not differences. Result: of 25 colour and shadow tokens, 21 differ in both themes, 1 (`--copper-ink`) differs in dark only, and 3 have no repo token: `--line-strong`, `--btn-line` and `--focus`. All 25 are used by mock rules, so none is dropped. The mock's light surface is `#FBFAF7` against the repo's `#fff`, and every neutral is a few steps warmer and darker in dark.

Three repo behaviours the mock does not share, for SNF-2 to settle:

- **Focus.** The mock draws `:focus-visible` as a 2 px outline in `--focus` (blue, `#1F5FBF` light, `#7FB0FF` dark) with a 2 px offset (`app.css` line 28). The repo's `button:focus-visible` in `apps/ui/src/components.css` uses `--accent`. The mock wins, so `--focus` is added.
- **Borders.** The mock has two: `--line` (hairline) and `--line-strong` (controls, segmented groups, chips, kbd). The repo has `--border` only. `--btn-line` is the near-black (`#2B2723`) outline of the default `.btn`.
- **Soft status fills.** The repo aliases them to entity fills (`--ok-soft` is `--character-soft`, `--info-soft` is `--place-soft`, `--danger-soft` is `--review-soft`) and derives `--warn-soft` with `color-mix` ([ADR 0590](../adr/0590-the-mock-fidelity-token-batch-fills-badges-with-opaque-soft-tokens-and-names-the-mocks-sizes-and-type.md)). The mock gives each its own value in both themes, and uses `--ok-soft`, `--bad-soft`, `--info-soft` and `--warn-soft` as the fills of pills, rows and the suggestion tones. Replacing the alias with the mock's value also stops the entity fills and the status fills moving together.

Where the repo has `-text` companions (`--danger-text`, `--warn-text`, `--info-text`, `--ok-text`, from [ADR 0059](../adr/0059-text-colours-meet-wcag-aa-with-two-text-levels-a-non-text-token-and-derived-on-tint-text.md)), the mock has none: it sets text in the status colour itself (`.pill.ok{color:var(--ok)}`), and its dark `--bad` and `--info` are lighter than the repo's `--danger` and `--info`. Which of the two passes 4.5:1 on the mock's soft fills is a SNF-2 contrast question; this note does not answer it.

## 6. Which superseded ADRs stay

The register supersedes ADR 0585, 0590 to 0667, 0645, 0650, 0670, 0715, 0720, 0725 and 0740 "where they differ", and the foundations PRD names ADR 0362, 0590 to 0640, 0585 and 0740. The two lists are not the same; ADR 0760 records the register's, plus 0362 and 0640 from the PRD. This section is the reading the "where they differ" clause needs for the ADRs this note can test. It is title-and-status level plus the tables above; an ADR not named in the first two groups was not tested against the mock here and keeps its status until the slice that swaps its page reads it.

**Differ from the mock, so the mock's value wins (tokens and primitive sizes, section 1 and 3):**

- ADR 0590 (token batch and sizes): the colour values, `--radius-card`, `--button-height`, `--button-height-sm`, `--row-height`, `--header-row-height`, `--font-size-page-title`, `--font-size-card-title`, `--font-size-label` and the two tracking tokens. The soft-fill aliases are replaced too.
- ADR 0362 (token batch, aliases, meter and badge colours): the status and badge colour values it derived. The meter-zone aliases are not in the mock.
- ADR 0595 (two button sizes, 32 and 28 px): the heights; the secondary and link looks are not tested here.
- ADR 0620 (`Kbd`): the 23 and 18 px heights against the mock's 12 px cap. The pressed bottom edge and Plex Mono agree with the mock, so those stay, and the ADR is extended, not superseded, by A16.
- ADR 0640 (panel header and body): the radius and header sizes.
- ADR 0585 and 0740 (scoring against the benchmark mocks): the benchmark is no longer a target. 0740's deletion of the per-PRD mocks and its text-blind scoring are not contradicted by the mock; D98 already retired the 90% bar. Both stop binding pages the mock covers.

**Agree with the mock or describe behaviour the mock does not draw, so they stay unless a page slice finds a difference:**

- ADR 0600 (one badge primitive with `pill`, `tag`, `booth` shapes): the primitive stays; the pill's measures change (section 3).
- ADR 0605, 0610, 0615 to 0619, 0625, 0630, 0635, 0636: these set sizes or behaviours of table, input, stat tile, level meter, tabs, overlays and the shell. The ones that fix a number the mock also fixes (0605 row and header sizes, 0615 and 0616 stat sizes, 0625 tabs, 0635 rail and header) are superseded by the mock's number where it differs and kept where it agrees; each page slice that uses the component re-reads the ADR. 0619 (`MeterBar` removed) and 0618 (`LevelMeter` ladder) are behaviour, not benchmark measures, and stay.
- ADR 0645 to 0670 (Production board, Proof notes, Booth word, rec pill, Master): page layouts measured on the benchmark mocks. Each is superseded when its page is swapped to the mock; none is superseded by this slice.
- ADR 0715, 0720, 0725 (Proof waveform card, Booth full window and F11, rail count badge and the Studio name): the register lists them under DQ-1 for layouts. 0725's count-badge rule is also overtaken by DQ-11 (the query badge goes with the Story Bible swap). 0720 and 0715 stay until the Booth and Proof swaps compare them with the mock.

The first group needs no further reading to be wrong; the second and third groups are the list the page slices read, so none is declared superseded wholesale by this note.
