# Studio Next gap audit: the built app against the mock

**Status: snapshot of `main` at `efbf4a31` (2026-10-19).** It lists what is still missing between the built app and the frozen Studio Next mock ([`docs/research/mockups/studio-next/`](mockups/studio-next/README.md)), so the remaining build can be cut into parallel pull requests. It is evidence, not kept current: the gap ids (PR-1, SB-4 and so on) are this note's own, and a PR that closes a row says so in its body.

Owner direction (D99): after the open PRs merge, finish the app toward the mock except where the owner decided otherwise. The rule is [Which mocks are the spec](../prds/studio-next-rebuild.prd.md#which-mocks-are-the-spec): the mock is a frozen reference, a departure supersedes its line in a PRD or doc, and the repo's old equivalent of anything in the mock is removed when the page is swapped in.

## What this note does not list

These are owner decisions or in-flight work, so none of them is a gap:

- **Settings.** Every setting stays on the Settings page. A setting that a page also offers is an extra, never always visible on the page (a hidden menu entry or a modal is fine). The Settings section lists only gaps outside that deviation.
- **Colour and form.** The map in [Colour and contrast](../design/colour-and-contrast.md#one-colour-and-one-form-per-kind) (CD1 to CD13): kind-based colour and shape, speaker colour from the entry, the find hit keeps `--search`, long silence is red, an open pickup is a warning, take identity has no hue. The colour pull requests (below) build it, and the statuses PR 7 is not open yet.
- **The header.** PR #2027 rebuilds it to the mock. The rail, jump menu, history panel and context menus are audited here.
- **Motion.** [Motion and animation](../design/motion-and-animation.md).
- **Mock lines the repo supersedes.** The table in the colour doc's "Mock lines this supersedes", and the amendments in the PRDs (grep `supersede` in `docs/prds/` and `docs/design/`).
- **Kept as built because the mock has no equivalent:** the stage timer, PFH and effective rate, the Series tab and series voice bible, the Companion, and (in Master & QC) the run controls, per-file rule list, Master to spec, mastering chain, Diagnostics, report and multi-platform export.
- **Decided on 2026-10-18:** Replace on import has no "what this changes" step and sets no chapter flags ([import review](../architecture/import-review.md)), so the mock's "Text changed" pill, Chapters to review dialog and the Next up "flags" item have no producer.

## Method

For each page I read the mock page source and the app page, the PRD slice table and the existing parity notes (`docs/research/studio-next-parity-*.md`), then compared screenshots. The mock was captured with `scripts/dev/capture-studio-next-mock.mjs` (1440 by 900, light and dark). The app was captured with `pnpm --dir src/studio/ui visual:page <pages>` in both themes, so each state has the visual suite's viewports. Every gap below was checked in code. The parity notes and several PRD phase tables are stale, so rows they list that are built now are left out ([Stale status](#stale-status-in-the-prds-and-parity-notes)).

Paths: a mock file name is relative to `docs/research/mockups/studio-next/src/` (`pages/`, `pages/<page>/` or `styles/` where the name alone is ambiguous), and an app path is relative to `src/studio/ui/src/components/` unless it starts with another top-level folder of `src/studio/ui/src/` (`input/`, `api/`, `primitives/`) or with `apps/`. Size is S (under a day, one area), M (a few files, tests and a guide update) or L (a new contract or host call).

## Headline

83 gaps in 12 areas: Production 6, Schedule 3, Proof 9, Editing 18, Booth 8, Script 8, Story Bible 8, Pickups 3, Master and QC 4, Delivery 5, Settings 5, shell and rail 6. Every PRD page slice is built and routed, and every page has its swap behind it, so what is left falls in four groups:

1. **Chrome and measures.** The shell pads `main` 24 px where the mock pads 16 (SH-3), the Script page pads nothing (SC-1), the Story Bible stops at `max-w-6xl` (SB-1), the Delivery aside is 320 px against 360 (DL-3), and Production's stat grid and the Schedule split differ at 1024 to 1280 (PR-3, SCH-1). Most of the Booth, Proof, Pickups and Settings rows are the same kind of drift. They are small, and the shell one moves every page's screenshots, so it goes first.
2. **Behaviour the mock has and the app lacks.** Editing's speaker chips, entity marks and Booth notes in the script text (ED-1 to ED-3); Master & QC's Clicks and Text columns and its waiting rows (MQ-1, MQ-2); the Story Bible's in-place relationship editor (SB-4); report sections the narrator can tick (PR-4); the Models folder actions (ST-3); the Booth side-panel pressed state (BO-2).
3. **Old-app leftovers.** Build / refresh beside Scan (SB-2), the alias combobox with its Review entry overlay (SB-5), Properties, Personality notes and per-kind context fields (SB-6), the Proof take panel for the recorder (ED-18), and the benchmark `mock-fidelity-01` state for Production (PR-6).
4. **Owner decisions the audit cannot make** ([list below](#decisions-for-the-owner)): bracket keys, Play ±3 s, chapter heading style, scope of an effect, and a few others.
