Mock files: c2-editing.test.tsx, d3-stacking.test.tsx, e-delete-range.test.tsx, e-fx-range.test.tsx, e-takes-inline.test.tsx

**Date:** 2026-10-12. **Code audited:** `main` at `c5d9187`, after the Editing swap (SN-E9, #1607, `0e11cca`). **Slice:** SN-C352 (#1211), SNC-3 of the [Studio Next cutover PRD](../prds/studio-next-cutover.prd.md). **Mock audited:** `docs/research/mockups/studio-next/tests/`. **Page PRD:** [studio-next-script-based-editing.prd.md](../prds/studio-next-script-based-editing.prd.md). SN-C4 reads this note when it flips the ratchets; SN-C51 and SN-C52 read it for the steady-state docs.

Method: each mock case is a row below, mapped to a real test by name. The real test was read, and the page code where a row's note says the page asserts less. The checker is `node scripts/ci/studio-next-parity.mjs`. It proves a cited test file exists and holds the name; it does not prove the test asserts what the mock case asserts. The app, REAPER and Audacity were not run, and the Playwright suites were not run. The cited real tests were run once (see [Verification](#verification)). The five files hold 125 cases by the checker's count (26, 39, 23, 20 and 17), as the slice text says.

## Result

- 125 mock cases: 79 `ported`, 39 `covered`, 7 `mock-only`. All 7 `mock-only` rows are gaps (their note starts `GAP`). 11 `covered` rows name a gap in their note. So 18 rows are open and 107 are not.
- 9 gaps (G1 to G9), under [Gaps](#gaps).
- **The duplicate-read split is not wired on the page** (G9). `EditingBody.tsx` mounts `useSplitDuplicate` with no `splitter`, so "Stack as 2 takes" and "Split into 2 takes" answer "Splitting a take is not available in this version yet." for every DAW and for the built-in recorder. The split tests pass because they inject a splitter. No split command exists in the DAW port or the bridge.
- **Nothing reads the Booth's passage map** (G1). The Booth writes it; Editing places every take as "aligned to the text". `passagetakes/evidence_test.go` `TestPlacementIsAlignedUntilTheMapExists` pins that on purpose.
- **Audacity has no take role** (G2, G5): it cannot keep a clip-take or hide takes. DS-2 and TK-3 leave Audacity clip-takes open.
- Delete range, FX on a range, stacking, hide and backups are on the page with DAW-first, one-entry journal commands, each with UI tests, Go adapter tests and Lua harness tests.
- Rulings: 10 agreed ids have a test row; TK-3 and DS-2 are `unclear` and listed with what the code does. See [Rulings](#rulings).
- Old equivalents: 7 checks. The old takes panel and per-passage FX dialog are gone from the UI. The host and Lua surface they used, and the cleanup split-and-delete path, is still in the tree with no UI caller: 3 leftovers (L1 to L3), each already owned by an open slice (#1308, #1311) or needing an owner call.
- No product test was added: the slice owns one file.

**The checker has no status for a gap.** A mock case with no real test must still have a row, and only `mock-only` passes with an empty `real test`. Gap rows therefore carry `mock-only` and a note that starts `GAP Gn`, as the other parity notes do. They are not excused: each has an entry under [Gaps](#gaps). SN-C4 should count them as open. A `covered` row whose note says `GAP Gn` has a real test that asserts less than the mock case, or tests a seam the page does not mount; it is open too.

Cases that call the DAW's range cut, range FX, roll or stack are `covered` by the DAW adapter's Go tests or the Lua harness, with the page's component test named in the note. What the fake REAPER cannot prove is in the owner's REAPER verification pass (SN-C2's list); every range, stack, hide and roll capability is still Experimental until that pass (`TestDeleteRangeIsExperimentalAndRefusedWhileTheSettingIsOff` and its siblings in `internal/bridge`).
