# Transcript Compare

**Status: Implemented, and its results are findings on Proof.** Each comparison's rows are saved as shared findings (the review dashboard), which [Proof](../guides/using-the-app/proof.md) lists, filters and decides, and from which it goes to, loops and marks a row in REAPER ([going to and looping a finding](../architecture/reaper-navigation.md)). Planned work is [#1454](https://github.com/countrymanprime/narration-studio/issues/1454).

`<app>` stands for values in `config/brand.json` ([Product and technical names](../architecture/codebase-map.md#product-and-technical-names)).

## Current capability and problem

The current local Faster-Whisper backend stitches a selected REAPER chapter track, matches it to a Word heading, and transcribes it; the host diffs the words against the chapter for misreads, skipped words, and extras (`src/studio/desktop/internal/comparerun`). It saves a unified diff and supports custom equivalences, hotwords, chunking, cancellation, and model selection. It finds likely read errors without a cloud service.

## Workflow

Select a chapter track, confirm its manuscript mapping and settings, run comparison, review each discrepancy and any existing matching markers, then explicitly select **Export markers** to add only new take markers.

## Inputs and outputs

- Inputs: REAPER item manifest, chapter-track name, canonical manuscript JSON, local model configuration, hotwords, and equivalence lists.
- Whisper model provisioning: the selected model (`config/whisper-assets.json`) is a catalog-managed, hash-verified local asset installed through the same first-use gate as Piper preview voices — see [First-Use Dependency Provisioning](../architecture/first-use-dependency-provisioning.md). Starting a comparison with a model that is not yet installed prompts to download it before anything runs; it no longer relies on `faster-whisper`'s own implicit, unverified download.
- Outputs: current marker protocol and diff files, and one `transcript_discrepancy` finding per row ([findings contract](../architecture/findings-contract.md), `src/studio/desktop/internal/transcript/findings_adapter.go`). The finding carries `confidence` and `timing_gap_seconds`, and Proof has a low-confidence filter. A `MARKER` line's 13th field, `repeat_of`, is set on an `EXTRA` whose words say the chapter text beside it again (the rule in [recording coverage](recording-coverage.md), `COVERAGE_EXTRA`'s `repeatOf`): that row is a `duplicate_read` finding with the repeated text as its expected text, which Proof shows as **Said twice**. The Lua bridge reads 12 fields and ignores it.
- Narrator actions: select chapter, set recognition controls, add reviewed equivalences and explicitly export new markers in a chapter's Proof view; on Proof, accept, dismiss or defer each finding, go to and loop it in REAPER, and add the marker for one accepted finding.

## Run identity and currency (proofing signals)

A comparison's result is kept beyond the one `.narration-last-comparison.json` slot for the proofing pickups signal (see [pickups.go](../../src/studio/desktop/internal/proofing/pickups.go), `src/studio/desktop/internal/proofing/compare.go`). No Lua, Python or marker-protocol change is involved; everything comes from files a run already writes.

- **Identity.** When a run finishes, the host writes one analysis evidence ledger record (`<project>/<app>/analysis/ledger/`, analyzer `transcript-compare`): the chapter resolved from the run's chapter title through the manuscript (the rows' chapter, else compare.py's `MATCH: '<title>'` summary, else the chapter the narrator chose), the manuscript's `documentId`, the model, the saved project file's modified time at completion, and the compared set read from `manifest_<run>.txt` (per item: source file and its identity under the ledger's hash policy, start offset, played length). A clean run gets a record too, so its chapter no longer lives only in the summary string, and comparing chapter 3 leaves chapter 2's record. A run that errors records `failed`; a cancelled run records nothing. A title that more than one chapter has is recorded without a chapter, and each such chapter reads unknown until the titles are distinct.
- **A clean run is a full run.** A complete run with no rows now saves an empty set for its chapter in the findings store, so the chapter's earlier findings are marked `not_in_latest_run` exactly as a run with rows marks the rows it did not reproduce.
- **Currency.** The run is current for a chapter only when it is that chapter's latest run and complete, the chapter has exactly one confirmed track, the saved project file is newer than the run (the comparison ran on the live project; saving afterwards is what ties it to the saved one), and every played item of that track (not muted, audio, on a playing lane) matches a compared item by source identity, start offset (the take's `SOFFS`) and played length, within a millisecond. Identical copies need one compared line each. Extra compared items, such as muted ones, do not invalidate it. A played item with no match makes the run stale when some compared item is also left over (the audio was edited since) and incomplete otherwise (the selection left it out).
- **Resolution.** A finding the latest run did not reproduce counts as resolved only when that run compared its source file over its source time. Anything else stays open until the narrator dismisses it.

Unverified: whether REAPER's `D_STARTOFFS` equals the saved `SOFFS` for a take whose source is a trimmed section (the bridge writes `D_STARTOFFS`); such items would read as not compared, which errs toward unknown.

## Alignment and confidence

Discrepancy detection transcribes freely (Faster-Whisper, with word-level timestamps) and then diffs the transcript against the manuscript text — it does not align the manuscript directly to the audio. The host matches the track to a chapter before anything is decoded (`comparerun.Choose`: an exact display title after the narrator picks one, otherwise the track-name matcher of `internal/chaptermatch` with the project's equivalence list on both sides, and a pick when nothing matches confidently, without starting the sidecar). The sidecar (`compare.py`) then transcribes and writes the words it heard (`COMPARE_SEGMENT` and `COMPARE_WORDS` lines); the host builds the markers, the results file and the diff from them with the same alignment the recording check and the take comparison use (`internal/comparerun` over `internal/compare`, whose package doc holds the results format). As of this change, each marker also carries a `confidence` label (`high`/`medium`/`low`/`unknown`) and the raw `timing_gap_seconds` it was derived from: the audio-timing gap at the discrepancy's boundary, reusing the same natural-pause threshold already used to split audio into sentences. A tight/no-gap boundary is weaker evidence that a flagged discrepancy is a genuine misread/skip/insertion rather than a token-split artifact of the diff itself. This is a secondary, transparent signal only — not proof either way, same as ASR confidence itself (see Acceptance and risks below). Proof shows both on each finding and can hide findings scored under 50%.

A `MISREAD`'s confidence is also scaled by how alike the script's words and the heard words are in letters and sound (`internal/soundalike`, #2251 item 27). The scorer is a weighted edit distance: a letter swapped for one that sounds like it (M and N, B and P, D and T, a vowel for a vowel), a vowel or a doubled letter added or dropped, and two letters turned around each cost less than another change, and words both sides start or end with are left out. The finding's confidence is the timing score times 1 minus that similarity, or 1 minus the similarity alone when there is no timing label, and its evidence carries `sound_alike` (the similarity, 0 to 1). "MBA" heard as "NBA" scores 0.17 alone and "Veyra" heard as "verus" 0.40, where both were treated as certain. It is an ordering, calibrated on [`tests/fixtures/sound-alike/cases.json`](../../tests/fixtures/sound-alike/cases.json): the owner's examples and what Whisper heard against the script in the committed LibriVox recordings. A real misread that sounds like the script ("histories" read as "stories") scores low too, so Proof's under-50% filter hides it.

The [recording check](recording-coverage.md) reads this same alignment to tell how much of a chapter was read in order, including the unread head and tail that the markers ignore. `compare.py --coverage` transcribes one chapter's items from a JSON manifest, keeping one words file per item so a later check transcribes only what changed, and the host aligns the chapter to those words with a port of this alignment (`src/studio/desktop/internal/compare` and `internal/recordingcoverage`, [Recording Check (recording coverage)](recording-coverage.md)). The Home breakdown's **Check** starts it through the Go coverage service, from the saved REAPER project. A comparison of this `SequenceMatcher` alignment with a word-level DP on the synthetic fixtures kept `SequenceMatcher` ([How it works](recording-coverage.md#how-it-works)). The coverage mode adds output and never changes a marker: a golden file pins the markers for every recording-coverage fixture.

A heavier alternative — true forced alignment (aligning the manuscript directly to audio via a CTC/wav2vec2 model, e.g. WhisperX's approach) — was evaluated and deliberately deferred; it would be this project's first PyTorch dependency. See Alignment and confidence. It stays deferred for localizing where inside a take a read diverges (`compare.py --take-divergence`, [internal/takedivergence](../../src/studio/desktop/internal/takedivergence/divergence.go)), because the diff plus Whisper's word timestamps already localize a divergence to the one word the comparison view can shade. A divergence counts as localized when it has the right kind over the right span words (an extra before the right word, give or take one), its time overlaps the true one, and both boundaries are within 0.4 s, one word at 150 words a minute. `tests/divergence_harness.py` measures this on the 14 scripted takes in `tests/fixtures/divergence/cases.json`. With exact and with jittered (±0.15 s) word times, which `tests/test_divergence_harness.py` gates in CI, all 14 are localized with no false divergence and at most 0.12 s of error. Spoken by two Windows System.Speech voices and transcribed by Whisper `tiny`, `base` and `small` with and without a vocabulary hint (12 runs, 2026-09-23), no boundary was more than 0.25 s out and no run's median above 0.11 s; With the first voice, `small` with the hint localized 14 of 14 with no false divergence; smaller models and the faster second voice added false divergences (up to 14 for `tiny`) from misheard words. Every miss was an error in the words Whisper wrote (an invented name with no hint, smaller models mishearing words, Whisper dropping a stutter), which forced alignment would not fix and which it would hide as real misreads. These are synthetic voices, an optimistic bound for real sessions. The run found one fix: when a run of words is said twice, the alignment reports the earlier copy as the extra, since a narrator abandons the earlier read (`TestARestartTheDiffMatchedFirstIsStillTheEarlierCopy` in `divergence_test.go`). A misread just before the end of a take absorbs the unread words after it into one `misread`, and Whisper tends to start a file's first word at 0.00 s.

## Non-goals and review boundary

The transcript is not the authoritative performance record. The utility does not correct text, choose a take, or create markers for unrecorded chapter material. Analysis never writes markers automatically: it labels a result as already marked when a same-kind prefix occurs on the active take within 0.15 seconds, and the explicit export action skips those rows. It rechecks immediately before adding a marker and reports how many were added or skipped. Proof's approved marker for one accepted finding uses the same rule and the same name, so the two never mark a row twice ([Adding the approved marker](../architecture/reaper-navigation.md#adding-the-approved-marker)).

## Acceptance and risks

- Each existing marker becomes one navigable finding with the same text evidence.
- Re-runs do not duplicate equivalent unresolved findings or erase review history when audio is unchanged.
- Tests (`src/studio/desktop/internal/comparerun`, `src/studio/sidecars/transcript-compare/tests/`) cover: homophones, spoken numbers and split compounds producing no marker; an invented name spelled another way being a misread until a custom equivalence is added; a partial recording marking no skips outside the recorded span, while a skip inside it is marked; a spoken, omitted, misheard or reworded heading (title and subtitle) producing no marker; the reference-section filter; marker timing confidence; marker context; repeated-span detection; property tests for tokenizing, number merging and sentence splitting; the exact markers for every recording-coverage fixture, held by a golden file; and the whole results file, diff and two-pane pair for the recording-coverage and take-divergence fixtures and seeded chapters, held by `tests/fixtures/compare/results.golden.json`, which `compare.py` wrote before the markers moved to the host. Chunk seams (`transcribe_chunked`) and stale item mappings have no tests yet ([#1454](https://github.com/countrymanprime/narration-studio/issues/1454)).
- Main risk: ASR confidence is not proof of a spoken error; UI language must retain that distinction.
