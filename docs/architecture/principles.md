# Design principles

The rules the app's design shares, each with the document or code that makes it a rule and the question that tests a design against it. The two [ADRs](../adr/README.md) are the whole-repo decisions behind them; where this page and an ADR disagree, the ADR holds and this page is corrected.

A design that breaks a principle for good is recorded in the document that describes the current state. It is an ADR only if it reverses an existing ADR ([when to write one](../adr/README.md#when-to-write-one)).

## The principles

### Behaviour the narrator can trust

- **1. Findings suggest; the narrator decides.** An analyzer reports a finding with evidence and a confidence and may suggest one action; it never executes it. Every change to the project is triggered by the narrator, or by a consent they gave once, and can be undone. ([ADR 0002](../adr/0002-local-models-and-tools-come-first-so-the-app-is-free-to-use.md), [Adding the approved marker](reaper-navigation.md#adding-the-approved-marker) (Proposed), [narration_cleanup.lua](../../src/studio/integrations/reaper/narration_cleanup.lua) (Proposed), .) *Ask:* does anything in this change edit audio, the manuscript or the project without the narrator's action?
- **2. Nothing installs, downloads or changes the project without the narrator's click or a one-time consent.** The only automatic outward call is the daily check for a newer release, a metadata request. The update never installs without a click, a model never downloads without asking, chapter sync asks once per project, and a render needs its own one-time approval. ([ADR 0002](../adr/0002-local-models-and-tools-come-first-so-the-app-is-free-to-use.md), [guidegate.go](../../src/studio/desktop/guidegate.go), [Chapter sync](../guides/using-the-app/navigation.md#chapter-sync), [The REAPER bridge and its test harness](reaper-bridge.md) (Proposed).) *Ask:* what is the consent moment, and does the action refuse without it?
- **3. Unverified behaviour ships off.** A command built before the owner's verification pass is refused by the host until the narrator switches it on; promotion is two small edits in one pull request (the port's declaration and the bridge's experimental list) after the pass. ([The REAPER bridge and its test harness](reaper-bridge.md), [The REAPER verification pass](../operations/reaper-verification-pass.md) (Proposed), [The DAW port](daw-integration.md#the-daw-port) (Proposed).) *Ask:* is it Experimental until the owner's pass, and does the host enforce that in one place?
- **4. Local-first; the narrator's data stays on the machine.** Analysis is local; an online source is a Go-only port with a privacy rule and a key sealed in its own file; logs never carry content; a report leaves out amounts unless the narrator opts in. Owner ruling D72: reference data may be fetched freely, but the narrator's and authors' data never leaves. ([ADR 0002](../adr/0002-local-models-and-tools-come-first-so-the-app-is-free-to-use.md) (Proposed), [ADR 0002](../adr/0002-local-models-and-tools-come-first-so-the-app-is-free-to-use.md) (Proposed), [Reading a run](../operations/verification-tooling.md#reading-a-run), [Threat model](threat-model.md) (Proposed), [Status report](../guides/using-the-app/production.md#status-report) (Proposed).) *Ask:* what leaves the machine, to whom, under whose key, and is any content logged?
- **5. Say what was measured; unknown is unknown.** Progress shows real work, a figure comes from a measurement and not an estimate, a result from synthetic data is labelled provisional or uncalibrated, and a value that could not be measured says so. ([recordedlengths.go](../../src/studio/desktop/recordedlengths.go), [Settings](../utilities/recording-coverage.md#settings) (Proposed), [Editing and proofing: a synthetic signal-level corpus, provisional](../research/editing-and-proofing-corpus.md) (Proposed), [mp3header.go](../../src/studio/desktop/internal/measure/mp3header.go) (Proposed).) *Ask:* is any displayed number an estimate, and is every provisional result labelled?
- **6. Precision over recall; offer, do not force.** A guess is offered, and preselected only when confident. A confident two-way match may become a labelled, undoable auto link, and nothing a guess does overrides a manual choice. ([Story Bible entity-extraction accuracy](story-bible-entity-accuracy.md), [ADR 0002](../adr/0002-local-models-and-tools-come-first-so-the-app-is-free-to-use.md), [Tracks](../utilities/tracks.md) (Proposed), [Chapter sync](../guides/using-the-app/navigation.md#chapter-sync).) *Ask:* what happens when the guess is wrong, and can it override the narrator's own choice?
- **7. Identity, not position; a stale target is refused.** Things are found by GUID or id, not by a project position or timeline time (a source time inside a found take is fine). A target that no longer resolves changes nothing and is not replaced by a neighbour; a fallback goes to a named source, never to a guess. ([Going to and looping a finding in REAPER](reaper-navigation.md) (Proposed), [Resume: where REAPER is and where the prompter was](manuscript-teleprompter.md#resume-where-reaper-is-and-where-the-prompter-was) (Proposed), [From the Takes panel](reaper-bridge.md#from-the-takes-panel), [Manuscript line identity in the REAPER project](manuscript-line-identity.md).) *Ask:* what identifies the thing, and what happens when it is gone?

### Structure of the code

- **8. Reach engines and providers through ports.** Small interfaces with a registry and a capability descriptor; callers ask a resolver what is supported and do not name an adapter or branch on a DAW's kind, except REAPER-only services that have no Audacity equivalent. ([The DAW port](daw-integration.md#the-daw-port), [Provider ports](provider-ports.md) (Proposed), [The asset registry (implemented)](first-use-dependency-provisioning.md#the-asset-registry-implemented).) For DAWs, the [DAW reference](../reference/daw/README.md) lists which engine declares which capability. *Ask:* does the caller name a concrete adapter?
- **9. Boundaries are contracts, checked where they cross.** A payload between Go, Python, Lua and the UI has a schema, a golden file and a contract row; an event's vocabulary is part of the contract. ([Wire contracts: how data is checked where it crosses a boundary](wire-contracts.md), [The DAW port](daw-integration.md#the-daw-port) (Proposed), [Shared Findings Contract](findings-contract.md) (Proposed), [The DAW port](daw-integration.md#the-daw-port).) [Wire contracts](wire-contracts.md) lists them. *Ask:* which side owns the shape, and what fails if the other side drifts?
- **10. The host judges; the UI displays; Lua stays small.** Thresholds and judgements live in Go (applied on read where they can change); the UI only shows what the host reports; REAPER Lua keeps only what a running REAPER knows ([DAW integration](daw-integration.md#reaper-rules)). ([Exporting a report](../guides/using-the-app/master-and-qc.md#exporting-a-report) (Proposed), [judgement.go](../../src/studio/desktop/internal/coverage/judgement.go), [Settings](../utilities/recording-coverage.md#settings) (Proposed).) *Ask:* is any rule or threshold in the UI or in Lua?
- **11. Project data lives in files beside the project.** Sidecars hold decided and derived data (per-user data lives in the narrator's app-data folder). Decisions are append-only, files are written to a temporary name and renamed, derived data can be reset, a file kept for a different document reads as empty, a read across projects never writes into a sibling, and removing a chapter from recording is a reclassification, never a delete. ([The narrator's decisions](stage-recommendations.md#the-narrators-decisions) (Proposed), [Production](../guides/using-the-app/production.md), [Data files](../reference/data-files.md).) *Ask:* where does it live, what resets it, and what happens when the manuscript is replaced?

### Interaction and interface

- **12. Every action acknowledges within 100 ms; long work is a job.** The control is marked busy at once, cannot be fired twice, and long work reports real progress and ends with one job-ended event that the app announces (a toast, or the job's own dialog). ([The standard](interaction-feedback.md#the-standard), [Job-end events](interaction-feedback.md#job-end-events), [The asset registry (implemented)](first-use-dependency-provisioning.md#the-asset-registry-implemented), [Design system reference](../design/design-system.md).) *Ask:* what does the narrator see in the first 100 ms, and how does the job end?
- **13. Primitives own the look; pages compose them; the Studio Next mock is the spec.** App code never imports a vendor widget or writes a native button, text input or select. Where a primitive cannot draw a look, the primitive changes and the page does not restyle it ([design system](../design/design-system.md)). ([Base UI wrappers](../design/design-system.md#base-ui-wrappers), [CSS layering gotcha](../design/design-system.md#css-layering-gotcha), [Mock match](../operations/verification-tooling.md#mock-match); the rebuild PRD's [which mocks are the spec](../prds/studio-next-rebuild.prd.md#which-mocks-are-the-spec).) *Ask:* is this a new primitive or token, or a local restyle?
- **14. Accessibility is tested, not assumed.** Shipped text colours meet WCAG AA (user-chosen category colours are not guaranteed), axe runs on every state with a violation failing unless declared debt, and ARIA snapshots pin dialogs and navigation. ([Colour and contrast](../design/colour-and-contrast.md), [CI and releases](../operations/ci-and-releases.md), [Verification and code-health tooling](../operations/verification-tooling.md).) *Ask:* which states does the change add, and does each pass axe?

### Process

- **15. Mechanical rules become gates; judgment is left to review.** A rule that a tool can check is a lint or test that names its ADR; coverage is a ratchet; dead code is at zero; documentation currency is checked by path and text. ([Verification and code-health tooling](../operations/verification-tooling.md), [Coverage ratchet](../operations/ci-and-releases.md#coverage-ratchet), [Dead code (Knip)](../operations/verification-tooling.md#dead-code-knip), [Documentation gates](../operations/documentation-gates.md).) *Ask:* could the rule this change relies on be a check?
- **16. One decision per ADR ([ADR README](../adr/README.md)); planned work is a PRD deleted when built; a new page replaces the old in the same change.** ([Lifecycle of a PRD](../prds/README.md#lifecycle-of-a-prd),.) *Ask:* does this change leave an old page, doc or PRD behind?

## Standing constraints

These are not principles to weigh; they change only by a new ADR: Windows x64 is the only supported platform ([Supported platforms](../../README.md#supported-platforms)); the project is AGPL-3.0-or-later ([Contributing](../../CONTRIBUTING.md)); workflow actions are pinned and gated ([CI and releases](../operations/ci-and-releases.md)); the desktop shell is pinned to one Wails v3 beta ([ADR 0001](../adr/0001-the-app-is-written-in-go.md)); the Go host imports networking only in the asset download, the update ([ADR 0002](../adr/0002-local-models-and-tools-come-first-so-the-app-is-free-to-use.md)), the media route and the Merriam-Webster adapter ([ADR 0002](../adr/0002-local-models-and-tools-come-first-so-the-app-is-free-to-use.md) (Proposed)). That lint rule ([Verification and code-health tooling](../operations/verification-tooling.md)) fences the Go host only; it does not cover sidecars.
