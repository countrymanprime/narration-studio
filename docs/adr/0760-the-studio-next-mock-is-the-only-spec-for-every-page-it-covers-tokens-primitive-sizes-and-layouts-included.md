# 0760. The Studio Next mock is the only spec for every page it covers, tokens, primitive sizes and layouts included

**Status:** Accepted (owner ruling 2026-10-11; owner ruling D98 of 2026-10-11, register row DQ-1 and ADR row A1 in the [ADR register](../prds/studio-next-adr-register.prd.md); the [foundations PRD](../prds/studio-next-foundations.prd.md) says A1 needs no owner answer)
**Date:** 2026-10-11
**Supersedes:** [ADR 0585](0585-mock-fidelity-is-a-pixel-match-at-the-mocks-own-size-and-theme-scored-by-a-tool-that-reports-and-does-not-gate.md), [ADR 0590](0590-the-mock-fidelity-token-batch-fills-badges-with-opaque-soft-tokens-and-names-the-mocks-sizes-and-type.md) to [ADR 0667](0667-the-mastering-chain-s-steps-are-badges-and-the-last-one-is-accent-soft.md), [ADR 0645](0645-the-production-board-draws-mock-01s-cells-columns-and-layout-and-the-mock-wins-the-open-audit-layout-questions.md), [ADR 0650](0650-proofs-notes-card-composes-table-flush-statusbadge-and-panels-header-and-the-filters-move-behind-a-popover.md), [ADR 0670](0670-scripts-chapter-list-keeps-its-to-confirm-count-and-shows-no-checkmark-or-percentage-until-prep-depths-rollup-lands.md), [ADR 0715](0715-proofs-book-level-waveform-card-belongs-to-the-chapter-its-selector-names.md), [ADR 0720](0720-the-booth-fills-the-whole-window-and-f11-takes-the-window-fullscreen.md), [ADR 0725](0725-the-rail-draws-a-count-badge-only-from-a-count-the-host-reports-and-the-product-is-named-studio.md) and [ADR 0740](0740-mock-match-is-text-blind-and-a-diagnostic-and-only-the-benchmark-mocks-are-kept.md), and, from the foundations PRD, [ADR 0362](0362-studio-token-batch-aliases-meter-and-badge-colours-and-a-minimal-booth-override.md), each only where it differs from the mock

## Context

Until 2026-10-11 the spec for a page's look was the seven benchmark mocks (owner ruling D96, 2026-09-29), and a series of ADRs fixed token values, primitive sizes and page layouts to what was measured on them: the token batches (0362, 0590), the primitive sizes (0595 to 0640), the page layouts (0645 to 0670, 0715, 0720, 0725) and the pixel-match scoring (0585, 0740). The owner then replaced the benchmark with the Studio Next mock, `docs/research/mockups/studio-next/`, and ruled on 2026-10-11: "The mocks are the gold standard and if it is not in the mock it doesn't get built. If it exists already and has an equivalent somewhere in the Studio Next mocks then get rid of the old." That is D98 in the [agent train](../operations/agent-train.md#owner-standing-rules); the register records it for this ADR's subject as DQ-1.

The two places a worker reads the rule already say it. `.claude/rules/ui-spec-and-screenshots.md` ("Which mocks are the spec") and [Which mocks are the spec](../operations/agent-train.md#which-mocks-are-the-spec) were rewritten to D98 when it was ruled. What was missing is the decision record: the superseded ADRs still read as binding, and a worker who finds a token, a size or a layout in one of them cannot tell from the ADR that the mock now wins.

The sources that list the affected ADRs disagree slightly. The register's DQ-1 row names 0585, 0590 to 0667, 0645, 0650, 0670, 0715, 0720, 0725 and 0740; the foundations PRD names 0362, 0590 to 0640, 0585 and 0740. The measured differences between the mock's values and the repo's are in the [token and primitive diff note](../research/studio-next-token-and-primitive-diff.md), which also records which ADRs in these ranges stay.

## Decision

1. **The Studio Next mock is the only spec for every page it covers.** Layout, tokens (`docs/research/mockups/studio-next/src/styles/`), primitive sizes (`docs/research/mockups/studio-next/src/ui/` and its `primitives/`) and behaviour of a covered page are built to the mock. A worker adds no control, state or feature the mock lacks.
2. **Where an older ADR, a benchmark mock, an existing page or a measured value differs from the mock, the mock wins.** The ADRs listed under Supersedes are superseded to that extent and kept where the mock agrees. The ADR text is not edited (their Status lines stay as they are while this ADR is Proposed); the diff note is the record of where they differ.
3. **Features with no equivalent in the mock are left as built:** the series voice bible and Series tab, the companion, and the stage timer, PFH and effective rate. The benchmark mocks (`docs/research/mockups/audiobook-studio-benchmark/`) remain only as the reference for those, and are deleted with the old pages at cutover.
4. **The mock's mechanisms are not adopted where the repo's own ADRs are right for this repo.** The mock's global `app.css` classes are not ported ([ADR 0003](0003-tailwind-tokenized-primitives.md), [ADR 0009](0009-complete-tailwind-migration.md), [ADR 0017](0017-no-legacy-css-shadowing-tailwind.md)), its `style.zoom` is not used ([ADR 0201](0201-app-zoom-under-wails-v3-on-windows-runs-from-100-to-200-percent-and-reads-the-level-back-from-the-window.md)), and the theme stays one app-wide setting ([ADR 0010](0010-theme-switching.md), [ADR 0365](0365-the-theme-is-one-global-setting-and-the-booth-and-companion-follow-it.md)). The narrator sees the mock's look and behaviour either way.
5. **During migration the older decision still holds for code the mock has not replaced.** A slice that changes a behaviour an ADR names says so in its pull request. The mock-match score is not used for Studio Next pages; the owner compares screenshots ([UI PRs show their screenshots](../operations/agent-train.md#ui-prs-show-their-screenshots)).
6. **The rule text is not changed by this ADR.** `.claude/rules/ui-spec-and-screenshots.md` and the agent train's "Which mocks are the spec" section already state D98; this ADR records the decision behind them and edits neither.

## Consequences

- A worker who meets a token value, primitive size or page layout in one of the listed ADRs has one place that says the mock wins, and the diff note says which values differ.
- The listed ADRs keep their current Status lines. If this ADR is accepted, the Status line of each listed ADR (or the part of it that differs) is a follow-up edit, made once the superseding token batch and the page swaps have landed; until then the register's migration-period rule applies.
- Because the sources list the affected ADRs differently, this ADR lists the register's ranges plus 0362 and does not widen or narrow them. An ADR in a range that the mock does not contradict stays in force; the diff note says which were checked and which were not.
- A page the mock does not cover is not governed by this ADR, so a decision about the series voice bible, the companion or the stage timer is unchanged.
- The pixel-match scoring tool and its ADRs (0585, 0740) stop binding any page the mock covers; deleting the tool is a separate change at cutover.
- To change the rule, write a new ADR that supersedes this one.
