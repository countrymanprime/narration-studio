# 0860. A roll keeps the earlier audio as a take, and a range cut, a chain on a range and stacking move audio and never delete it

**Status:** Proposed
**Significance:** An interface between parts: four DAW commands (`roll`, `delete_range`, `apply_fx_range` and remove, `stack_takes` and `unstack_takes`) whose arguments, undo rule and refusals the Booth and Editing slices (SN-D61, SN-D62, SN-D63, SN-D71) and every DAW adapter build to. Reversing it changes the bridge commands, the `dawport` edit roles and the pages that call them.
**Date:** 2026-10-12
**Supersedes:** in part, [ADR 0246](0246-punch-and-roll-moves-only-the-edit-cursor-and-anchors-words-by-a-polled-play-position.md) (the roll), [ADR 0234](0234-fx-chains-go-on-tracks-and-a-passage-of-a-take-gets-one-plug-in-at-a-time.md) (chains only on tracks, for a range), [ADR 0705](0705-the-workspace-adds-an-effect-to-a-passage-or-a-chain-to-the-chapters-track-only-after-the-narrator-confirms-and-the-host-names-both-targets.md) (the chain on a range), [ADR 0147](0147-retakes-on-fixed-lanes-are-chosen-by-lane-play-state-and-the-app-never-converts-takes-and-lanes.md) (stacking, DQ-7) and [ADR 0262](0262-cleanup-trims-are-found-by-matching-the-measured-file-to-a-live-item-and-applied-as-a-split-and-delete-inside-one-undo-block.md) (the delete, DQ-8).

## Context

The Studio Next mock rolls while recording, cuts a range of words with its audio, puts a saved chain on a range and stacks retries as takes (`docs/research/mockups/studio-next/src/state/daw.ts`: `roll`, `deleteRange`, `applyFxToRange`, `removeFxFromRange`, `stackTakes`, `unstackTakes`; `tests/booth-daw.test.tsx`, "Punch and roll"). The [DAW PRD](../prds/studio-next-daw-ports-and-capabilities.prd.md) asks for them as commands (Proposed Solution item 1, and its Decisions DQ-7, DQ-8 and the process defaults), and [the register](../prds/studio-next-adr-register.prd.md) rows A8 and A9 name the ADRs they contradict. The catalogue rows and the DAW-neutral roles already exist (`cut_range`, `fx_range`, `stack_takes` in `apps/desktop/internal/dawport/capability.go`; `RangeCutter`, `RangeFXApplier`, `TakeStacker` in `roles.go`); no REAPER command does.

The PRD meant this ADR to follow spikes SND-S1 to S4. On 2026-10-12 the owner deferred every manual run to the QA pass ([#1495](https://github.com/countrymanprime/narration-utils/issues/1495)); the spikes' issue closed as deferred and [their results note](../research/studio-next-daw-spike-results-reaper.md) has no result. So this ADR rests on what is documented, and marks the rest:

| REAPER behaviour | Source |

| A change wrapped in `Undo_BeginBlock2(0)` / `Undo_EndBlock2(0, label, -1)` is one undo step; a command that changes nothing opens no block | [REAPER reference, "What REAPER was seen to do"](../reference/daw/reaper.md#what-reaper-was-seen-to-do), Undo row (7.80) |

To be confirmed in the QA pass (#1495): which setting of REAPER's "new recording that overlaps existing media items" option keeps the earlier audio as a take and how a script reads it; how many undo points a roll's stop and restart leave; whether `TakeFX_AddByName` loads a `.RfxChain` onto a take, by which name form, and how many FX it adds; whether a split, a move to another track and a close-up in one block are one step and leave other items correct; whether a stack with cross-track moves is one step; and whether a track's `P_EXT` survives save and reload as an item's does.

**Considered options:** wait for the spike runs (the owner deferred them, and four slices block on this contract); keep ADR 0246's cursor-only roll and ADR 0234's one plug-in per passage (the mock and DQ-7, DQ-8 rule otherwise); have each command change the narrator's recording preference when it is wrong (the process defaults forbid it); split and delete for a cut (DQ-8: never delete); and the chosen one: build each command to the documented calls, make each refuse what it cannot do, and let the QA pass correct the rows marked above.

## Decision

Every command below is Experimental behind its capability ([ADR 0230](0230-reaper-commands-built-before-the-verification-pass-are-refused-by-the-host-while-the-experimental-switch-is-off.md), [ADR 0400](0400-promoting-a-reaper-command-from-experimental-to-supported-is-a-one-line-daw-port-declaration-change.md)), answers a `dawport.Result` ([ADR 0810](0810-a-daw-call-answers-one-result-object-and-a-capability-reports-whether-it-is-destructive-and-its-mode.md)), re-resolves every item and take by GUID and refuses a stale one with the `stale` code ([ADR 0861](0861-a-refused-daw-call-carries-one-code-stale-beside-its-sentence.md)), and takes no path, file or action name from the page. Except `roll`, each refuses while the DAW records. The PRD places the Lua in `narration_takes.lua` and a new `narration_range.lua`, registered in `FEATURE_FILES`, with its argument lists.

1. **Roll is one command that keeps the earlier audio as a take.** `roll(run, track_guid, at)` serves the `punch` capability with a destructive flag. It runs only while a recording this bridge started runs on that track ([ADR 0232](0232-arming-for-a-recording-remembers-the-narrators-arms-makes-no-undo-point-and-the-app-stops-only-the-recording-it-started.md)), and refuses otherwise. Since the recording is not an item until it stops, the command stops it, moves the edit cursor to `at`, and starts recording there with `CSurf_OnRecord`, so the new recording overlaps the earlier one. It reads REAPER's overlap-recording option first and refuses, naming the option and the setting it needs, unless that option keeps the overlapped audio as a take (which setting does, and how a script reads it, is to be confirmed in the QA pass (#1495)); it never changes the narrator's recording preferences. REAPER declares the roll non-destructive, on the condition that the QA pass confirms such a setting. An engine where a roll would replace audio declares `destructive: true` and the page asks before rolling (Audacity without backups, as the mock does). The command opens no undo block of its own; `undoSteps` is 0, and the points REAPER adds for the recorded media are REAPER's (how many is to be confirmed in the QA pass (#1495)). `punch_to` and `play_position` stay as ADR 0246 built them.
2. **A range cut splits at both ends and moves the middle to a muted Cuts track, in one undo block.** `delete_range(run, item_guid, start, end, mode, fade_ms)` serves `RangeCutter.DeleteRange`. In one block it splits the item at `end` and then at `start`, and moves the middle piece with `MoveMediaItemToTrack` to the project's Cuts track: muted, found by a track `P_EXT` key the bridge writes, and created in the same block when the project has none (whether a track's `P_EXT` survives save and reload is to be confirmed in the QA pass (#1495); if it does not, the command finds the track by its name). Mode `close` moves the later items on the same track up by the cut's length; `gap` leaves them and fills the cut with room tone (the [catalogue row](../reference/daw/capabilities.md#cut_range)). Items on other tracks never move. Nothing is deleted and no source file is touched (DQ-8). Silence-cleanup trims ([ADR 0262](0262-cleanup-trims-are-found-by-matching-the-measured-file-to-a-live-item-and-applied-as-a-split-and-delete-inside-one-undo-block.md)) move their middle pieces the same way instead of calling `DeleteTrackMediaItem`.
3. **A chain on a range is one of the narrator's saved chains, by name, on the split piece, and removing it joins the piece back.** `apply_fx_range(run, item_guid, start, end, chain, fade_ms)` serves `RangeFXApplier.ApplyFXToRange`. `chain` must be a name `list_fx_chains` holds; the Lua builds the path under `FXChains` as `apply_fx_chain` does ([ADR 0234](0234-fx-chains-go-on-tracks-and-a-passage-of-a-take-gets-one-plug-in-at-a-time.md) point 1). In one block it splits at both ends, adds the chain to the middle piece's active take with `TakeFX_AddByName(take, path, -1)`, checks that the take's FX count grew (whether this loads a chain onto a take is to be confirmed in the QA pass (#1495)), and writes the chain name and the number of FX added to the take's `P_EXT`. A chain that adds nothing is refused as `failed`, and the answer says one Undo rejoins the item, as `add_take_fx` does. The remove command, serving `RemoveFXFromRange`, takes off only the FX that `P_EXT` records and joins the piece to its neighbours in one block; how it joins them is SND-6c's to choose. The page still names words and a chain, the host resolves the item, and nothing is sent before the narrator confirms ([ADR 0705](0705-the-workspace-adds-an-effect-to-a-passage-or-a-chain-to-the-chapters-track-only-after-the-narrator-confirms-and-the-host-names-both-targets.md) points 1, 3 and 4).
4. **Stacking moves later reads onto the first read as takes, and un-stacking restores them by recorded offsets.** `stack_takes(run, payload_path)` serves `TakeStacker.StackTakes` with one row per move of a `StackRequest`. In one block, for each group, each later read becomes a take of the base item (`AddTakeToMediaItem`, its source, `D_STARTOFFS` aligned to the read); its own item moves to the muted Cuts track; the take's `P_EXT` records that item's GUID, its track and its start; and the audio after the group moves up by the request's `Shift`. The first read stays active ([ADR 0233](0233-the-app-may-make-a-take-active-by-guid-in-one-undo-step.md) is the only way to change it). A read longer than the base item is refused, since adding a take leaves `D_LENGTH` unchanged. A fixed-lane track is refused, and the app still never sets `I_FREEMODE` or converts lanes (ADR 0147's lane rules). `unstack_takes` reverses one stack from what `P_EXT` recorded: it moves each item back to its recorded track and start, removes the take it became, and moves the following audio back, in one block.
5. **One block per call.** Each command wraps its edits in one undo block, which REAPER makes one undo step (the Undo row of the reference). Whether that holds for splits, a move to another track and a close-up together is to be confirmed in the QA pass (#1495); until then `undoSteps` is 1 for a cut, a chain, a removal, a stack and an un-stack. Where the QA pass finds a command takes more than one step in REAPER, the command reports the steps (`mode: steps`, `Steps`) or refuses; it does not hide the extra points.

## Consequences

- The Booth and Editing slices can build roll, cut, chain on range and stacking against fixed arguments, refusals and undo counts now, and run unchanged on a second DAW through the same roles.
- Nothing the narrator recorded is deleted by the app: cuts and stacked reads sit on the muted Cuts track, and a split piece keeps its line id (S0), so the host must ignore items on the Cuts track when it maps words to items.
- The roll depends on the narrator's overlap-recording setting. If it is wrong, the Booth shows the refusal and the narrator changes it in REAPER; if the QA pass finds no setting keeps the earlier audio as a take, roll is withdrawn from REAPER and ADR 0246's cursor-only roll stays.
- If the QA pass finds `TakeFX_AddByName` does not load a chain onto a take, `apply_fx_range` refuses chains and point 3 is superseded by a new ADR; ADR 0234's one plug-in per passage still works.
- Every row of the QA list in the Context is a check the command slices add to the QA pass (#1495); a result that differs opens a fix slice.
- The superseded parts of ADRs 0246, 0234, 0705, 0147 and 0262 stay in force for code not yet migrated until each command lands. ADR 0232, 0233 and [ADR 0302](0302-dawport-roles-exchange-the-bridges-own-types-through-aliases-and-an-asynchronous-role-is-one-method-per-command.md) are kept.
- Changing any of the four decisions needs a new ADR that supersedes this one.
