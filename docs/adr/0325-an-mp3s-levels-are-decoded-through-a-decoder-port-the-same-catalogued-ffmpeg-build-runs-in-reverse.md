# 0325. An MP3's levels are decoded through a Decoder port, the same catalogued FFmpeg build run in reverse

**Status:** Proposed
**Date:** 2026-09-27
**Amends:** [ADR 0237](0237-an-mp3-is-measured-for-its-container-only-from-bounded-frame-headers-and-its-levels-are-not-checked.md) (its "levels are not checked" holds only when no Decoder is available; its container-only header reading is unchanged and stays the only way `Report.MP3` is built)

## Context

ADR 0237 measures an MP3's container from its frame headers only, and leaves `acx.rms`/`acx.peak`/`acx.noise_floor` "not checked": decoding compressed audio was out of its scope. This ADR adds it: decode through the same encoder dependency the MP3 render already needs (one dependency, one license record, not a second MP3 decoder), then measure the decoded PCM with `internal/measure`'s own hand-written meters, unchanged (ADR 0025's "no third runtime" is about the measurement algorithms, not about turning compressed bytes into samples).

The `Encoder` interface (PR #746) shipped its encode direction only (`internal/encodeport`, WAV to MP3). Its decode direction did not exist yet, and decoding levels depends on it. Rather than wait for a separate change, this ADR adds the decode side itself, as a new file inside the same package, reusing the FFmpeg executable and process-supervision plumbing `UseFFmpeg`/`ffmpegRow` already wires in at start.

## Decision

1. `internal/measure` declares its own `Decoder` interface (`DecodeToWAV(ctx, src, dst string) error`) and an `Options.Decoder` field. It depends on this interface only, never on a concrete adapter: `internal/encodeport` already imports `internal/measure` (for `ReadMP3`, to check its own encoder output), so `measure` cannot import `encodeport` back without a cycle.
2. `internal/encodeport` gains a `Decoder`/`Decoders` registry beside its existing `Encoder`/`Encoders`, in a new file (`decode.go`); the FFmpeg row registers itself in both, Windows only, sharing the same `locate`/process-supervisor state `UseFFmpeg` sets. `(*FFmpeg).DecodeToWAV` follows `Encode`'s own chain-of-custody rules exactly: refuses a destination equal to its source (any spelling, or a hard link) or one that already exists, writes a dot-named partial beside the destination, confirms it with the app's own WAV reader, and only then renames it; a cancelled context or a timeout (twice the source's nominal length plus five minutes, from its own header-only duration) leaves nothing behind.
3. The host (`apps/desktop/mp3decode.go`) is the only place the two packages meet: `mp3LevelDecoder()` looks up the `Decoders` row for the current platform and wraps it, translating `encodeport.ErrEncoderNotInstalled` into `measure.ErrDecoderNotAvailable`. `measure_job.go`'s `runMeasure` passes it as `Options.Decoder` on every measurement.
4. `measure.MeasureFile` (`decode.go`), once it has read an MP3's container (as ADR 0237 describes, unchanged), decodes it with `opts.Decoder` when one is given and merges the decoded audio's own measurement (RMS, peaks, noise floor, room tone, clipping — the same fields a WAV report already carries) into the report, alongside the still-present container info. `Report.MP3LevelsDecoded` records whether a decode was actually attempted, distinguishing three outcomes that would otherwise all look like "every level field is null": no `Decoder` was available (`MP3LevelsDecoded` false, exactly ADR 0237's own behaviour, rule status stays `not_checked`), a decode was attempted and produced usable values (rule status `met`/`not_met` like a WAV), and a decode was attempted and produced nothing usable — a corrupt or truncated file, or an installed-but-unreachable encoder (`MP3LevelsDecoded` true with null fields, rule status `not_measurable`, never a fabricated value). `internal/deliveryprofile`'s `otherKindWhy` reads this flag to choose between "not checked" and letting the normal not-measurable path apply.
5. The container measurement itself (bitrate, CBR, sample rate, channel mode) is still read from frame headers only and is never replaced by anything the decode produces; `acx.format` and friends are unaffected by this ADR.

## Consequences

- ACX's RMS, peak and noise-floor rules can be met, not met, or not measurable on an MP3, not only "not checked", on any machine with the catalogued FFmpeg encoder installed (Windows only, matching the MP3 render's own scope).
- The book-wide spread (PR #763) and the Review-page findings (PR #748, [ADR 0322](0322-delivery-findings-are-saved-for-review-per-measured-file-versioned-by-the-audio-and-the-rules-bound.md)) both read these same rule results and need no change of their own: an MP3's levels start contributing to both the moment they are measured.
- `internal/encodeport` now exposes a decode direction beside the encode direction; later encoder work should treat `decode.go` as already there rather than re-adding it.
- Decoding reaches FFmpeg's full MP3 demuxer and decoder, a larger attack surface than ADR 0237's own bounded header-only Go parser (threat model row 1g, added alongside this ADR). No privilege is crossed: the process runs with the narrator's own rights, in the existing Job Object, on a file already validated as a well-formed MP3 by the bounded parser first.
- Superseding this needs a new ADR, for example if a second decode path (a different codec, or a pure-Go decoder) is added later.
