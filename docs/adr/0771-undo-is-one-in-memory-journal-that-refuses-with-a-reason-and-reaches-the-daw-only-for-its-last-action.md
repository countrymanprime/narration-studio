# 0771. Undo is one in-memory journal that refuses with a reason and reaches the DAW only for its last action

**Status:** Proposed (owner rulings SNS-Q3 and SNS-Q4 of 2026-10-11, register row A6; both were taken as defaults under the standing instruction, for acceptance on [#992](https://github.com/countrymanprime/narration-utils/issues/992))
**Date:** 2026-10-11
**Supersedes:** none. It keeps [ADR 0202](0202-a-confident-two-way-match-is-a-real-link-labelled-auto-undoable-and-never-over-a-manual-one.md), [ADR 0120](0120-findings-are-read-and-decided-through-four-generic-bindings-and-a-decision-carries-the-evidence-version-it-was-made-against.md) and [ADR 0233](0233-the-app-may-make-a-take-active-by-guid-in-one-undo-step.md) as journal targets

## Context

The Studio Next mock has one undo history for every page. `docs/research/mockups/studio-next/src/state/store.ts` caps it at 40 entries; `undoEntry` refuses with a sentence when the entry is already gone ("Already undone."), when it is a DAW change and anything came after it ("Undo 'X' first. It came after this."), when REAPER's last action is something else ("REAPER's last action is not this one, so it was left alone. Use Edit > Undo in REAPER."), and when a later entry changed the same data ("Undo 'X' first. It changed the same thing."). `src/app/history.tsx` lists the entries newest first and offers Undo on the newest; a toast from `src/ui/overlay.ts` (`toastUndo`) offers Undo for exactly the entry it reports. `tests/foundations.test.ts` covers the DAW-last refusal.

The real app has undo per feature and nothing spanning them: auto links undo one link ([ADR 0202](0202-a-confident-two-way-match-is-a-real-link-labelled-auto-undoable-and-never-over-a-manual-one.md), `ChapterSyncUndo`), the findings store keeps an append-only decision history where status `unreviewed` reopens a decision ([ADR 0120](0120-findings-are-read-and-decided-through-four-generic-bindings-and-a-decision-carries-the-evidence-version-it-was-made-against.md), `FindingsReview`), and each REAPER command adds one undo block ([ADR 0233](0233-the-app-may-make-a-take-active-by-guid-in-one-undo-step.md)).

[ADR 0770](0770-the-ui-store-caches-host-reads-and-journals-commands-and-the-go-host-stays-the-source-of-truth.md) replaces the mock's inverse patches with journal entries that hold inverse host commands. That leaves the scope of undo to settle: which changes it covers, how long it remembers, when it refuses, and whether it can reach the DAW. The rebuild PRD's register lists undo spanning the DAW as conflict A6, with no existing ADR and a spike needed (`docs/prds/studio-next-rebuild.prd.md`, "Unverified behaviours that must be spikes", item 6). The domain-state PRD's Supersedes table records the rule "a DAW entry is undoable only when it is the last entry and the DAW reports it is still its last action; otherwise the refusal names the DAW's own Edit > Undo", and its rulings SNS-Q3 (40 entries, cleared on project switch) and SNS-Q4 (the mock's `act` list is the starting set; a command with no safe inverse is non-undoable in-app).

## Decision

1. **One journal covers UI-only, host and DAW changes.** Every change a page makes through `act` ([ADR 0770](0770-the-ui-store-caches-host-reads-and-journals-commands-and-the-go-host-stays-the-source-of-truth.md)) adds one entry `{ id, label, daw, touches, undo }`. The label is the sentence the history list and the refusals show ("Added a bookmark"). One narrator action is one entry, even when it calls several host commands.
2. **The journal holds the last 40 entries, in memory only.** The oldest falls off at 41. It is cleared on project switch and starts empty at launch. It is not persisted, and it never spans projects.
3. **An entry touches named keys, and a later entry on the same key blocks it.** `touches` lists read-model keys as `domain/id` (`bookmarks/12`, `findings/f-3`, `stages/ch-4`) or a whole domain (`milestones`). Two keys overlap when one is a prefix of the other. `undo(id)` refuses with "Undo 'X' first. It changed the same thing." when any later entry overlaps, naming the newest such entry, and changes nothing. Undo of the newest entry is `undoLast()`; undo of any other entry is allowed when nothing later overlaps it, as in the mock.
4. **A DAW entry is undoable only when it is the last entry and the DAW reports it is still its last action.** An entry with `daw: true` is refused with "Undo 'X' first. It came after this." when any entry follows it, and with "*DAW*'s last action is not this one, so it was left alone. Use Edit > Undo in *DAW*." when the DAW reports a different last action. Until the DAW port can report and undo its own last action (spike 6 in `docs/prds/studio-next-rebuild.prd.md`, owned by the DAW Ports and Capabilities PRD), every DAW entry is refused with the second sentence: the app does not claim to reach the DAW's history. When an entry has an app-side part as well (a findings decision with a kept take), that part is undone only after the DAW part succeeds.
5. **The host may refuse an inverse, and the refusal is shown as it comes.** An inverse is a host command and can be refused: a finding whose evidence changed (`FindingsReview`), a stage whose basis changed (`StageConfirm`), an id the host no longer has. The journal shows the host's sentence, keeps the entry, and changes nothing. A thrown or malformed answer shows "That change could not be undone." as the mock does.
6. **An inverse that recreates gives the thing a new id.** Where the only inverse of a delete is a create (`ManuscriptCreateBookmark`, `ManuscriptCreateNote`), the host assigns a new id. The journal applies the new id to the read model; an earlier entry that names the old id is refused by the host as in rule 5.
7. **A command with no safe inverse is journalled as not undoable in-app.** The entry is listed so the history stays true, and Undo on it refuses with a sentence naming why; for a DAW change the sentence names the DAW's own Edit > Undo. The starting set of commands, with each one's inverse or reason, is `docs/research/studio-next-undo-inverse-table.md`. A slice that adds a host command states its inverse in the same slice, or marks it not undoable in-app with the reason.
8. **Redo is not built.** An undone entry leaves the journal; nothing restores it. The existing mechanisms ([ADR 0202](0202-a-confident-two-way-match-is-a-real-link-labelled-auto-undoable-and-never-over-a-manual-one.md), [ADR 0120](0120-findings-are-read-and-decided-through-four-generic-bindings-and-a-decision-carries-the-evidence-version-it-was-made-against.md), [ADR 0233](0233-the-app-may-make-a-take-active-by-guid-in-one-undo-step.md)) stay as they are and become what journal entries call; the findings store keeps its append-only history, so an undone decision is a new `unreviewed` record, not a deletion.

## Consequences

- The narrator gets one history across pages, and a refusal always says what to do next: undo a named later change first, or use the DAW's own Edit > Undo.
- Until spike 6 reports, no DAW change is undoable in-app, which is fewer than the mock offers: in the mock, undo of a DAW entry restores only the app's copy and assumes the DAW followed. The history list still shows those entries with their DAW label. The spike result is owner-verified in REAPER (pending on [#992](https://github.com/countrymanprime/narration-utils/issues/992) through the DAW Ports and Capabilities PRD), and rule 4 changes only in what the port reports, not in its sentences.
- Most mock commands are not undoable in-app on today's host (33 of 44 in the table), largely because their forward command does not exist yet. The undoable share rises only as page slices add commands with inverses; the PRD's 90% target is not met by this ADR.
- An in-memory journal loses its entries on a crash or restart. That is by ruling SNS-Q3; the data itself is on disk through the host.
- Prefix overlap on keys refuses some undos that would have been safe (two edits to different fields of one bookmark). A finer key is a later change to `touches`, not to these rules.
- To persist the journal, add redo, or undo through the DAW's history without the last-action check, write a new ADR that supersedes this one.
