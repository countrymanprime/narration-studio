# 0770. The UI store caches host reads and journals commands, and the Go host stays the source of truth

**Status:** Accepted (owner ruling 2026-10-11; owner rulings SN0-Q3 and SNS-Q2 of 2026-10-11, register rows A5 and A17; SNS-Q2 was taken as the default under the standing instruction)
**Date:** 2026-10-11
**Supersedes:** none. It keeps [ADR 0041](0041-host-bindings-read-project-services-through-one-snapshot-accessor.md) and [ADR 0069](0069-payloads-are-validated-with-zod-behind-parsewire-and-a-wrong-shape-fails-loudly.md)

## Context

The Studio Next mock keeps the whole book in the browser. `docs/research/mockups/studio-next/src/state/store.ts` holds one `StudioState` (`data` is the book, `ui` the page state), changes it with immer's `produce` in `update(fn)`, and in `act(label, fn, {daw, restoreUi})` records immer's inverse patches as a history entry that `undoEntry` applies to take the change back. Every page reads it through `useStudio(selector)` over `useSyncExternalStore`, and the selectors in `src/selectors/` derive every shown number from it.

The real app has no such store. Domain state lives in Go services and sidecar files, and bindings read it through one snapshot accessor ([ADR 0041](0041-host-bindings-read-project-services-through-one-snapshot-accessor.md)); the UI parses each payload with Zod behind `parseWire` ([ADR 0069](0069-payloads-are-validated-with-zod-behind-parsewire-and-a-wrong-shape-fails-loudly.md)) and pages keep what they fetched in their own hooks. Undo is per feature: a toast button, a host undo block, a REAPER undo step ([ADR 0233](0233-the-app-may-make-a-take-active-by-guid-in-one-undo-step.md)).

The mock is the spec for how pages behave ([ADR 0760](0760-the-studio-next-mock-is-the-only-spec-for-every-page-it-covers-tokens-primitive-sizes-and-layouts-included.md)), but adopting its store would put a second copy of the book next to the host, and inverse patches over that copy cannot undo a change the host already wrote. The rebuild PRD's register lists the whole-book store as conflict A5 and the `immer` dependency as conflict A17, folded into A5. The owner ruled SN0-Q3 (the store is a read-model cache plus a command journal; the host stays the source of truth) and SNS-Q2 (no immer; journal entries hold inverse host commands; UI-only slices use small copy-on-write helpers), recorded in `docs/prds/studio-next-domain-state-and-contracts.prd.md` "Decisions" and on #993.

## Decision

1. **The UI store holds read models, not the book.** `apps/ui/src/studio/` holds a typed store of read models: what pages show, such as a production overview, a chapter's notes, the pickups list, bookmarks, and the DAW's capabilities and project state. Each is hydrated through a port, parsed by `parseWire`, and refreshed when the host's events say it changed (`job:ended`, `pickups:state`, `daw_capabilities_changed` and the like) or on focus. The store never writes a read model the host did not return, except to apply a command's result. Selectors derive every shown number from read models, as the mock's do from its book. The mock's whole-book `StudioState` and its `makeBook` data are not adopted as runtime state; `makeBook`-style builders are fixtures only.
2. **The Go host stays the source of truth.** Domain state is read and written only through host bindings ([ADR 0041](0041-host-bindings-read-project-services-through-one-snapshot-accessor.md)); the store is a cache that can be thrown away and rebuilt from the host at any moment. After a restart or a project switch the store starts empty and hydrates again.
3. **Every change goes through one journalled command path.** `act(command)` takes `{ label, touches, daw, run, undo }`, runs `run` (a host command through a port, or a UI-only change), records a journal entry holding the inverse (a host command, or for UI-only state a closure), and returns a `Result`. The undo rules, the journal's size and what may be refused are [ADR 0771](0771-undo-is-one-in-memory-journal-that-refuses-with-a-reason-and-reaches-the-daw-only-for-its-last-action.md). The mock's `act(label, fn, {daw, restoreUi})` maps onto it: `label` and `daw` carry over, `touches` replaces the patch paths, `restoreUi` becomes the UI part of the inverse.
4. **No immer, and no state library.** The app takes no `immer`, Redux or Zustand dependency. UI-only slices (a selection, a filter, an open drawer) change through small copy-on-write helpers in `apps/ui/src/studio/` that return a new object for the changed path and keep the identity of everything else, so `useSyncExternalStore` selectors that return a slice stay stable. A UI-only inverse is the previous value of the changed path, captured by the helper.
5. **Only cross-page state belongs in the store.** State one component owns stays in that component. A read model enters the store when two pages, or a page and the rail, show it.

## Consequences

- One persistence path: a change is on disk when the host answers, and nothing in the UI can disagree with it for longer than one event. A crash loses only the journal, never data.
- The mock's undo by inverse patches is replaced by inverse host commands, so a command is only undoable in-app when the host has a command that takes it back. The mapping for every mock `act(...)` call is `docs/research/studio-next-undo-inverse-table.md`: on today's host 11 of 44 have one. Slices that add a host command add its inverse with it, or mark the command not undoable in-app with the reason.
- Selectors stay pure functions, but of read models rather than of a book, so a selector that needs data no read model holds needs a host read first. Pages cannot compute from data the host never sent.
- Read models can go stale between events. The mitigations are hydration on events, refetch on focus, and the host refusing an inverse whose basis changed ([ADR 0771](0771-undo-is-one-in-memory-journal-that-refuses-with-a-reason-and-reaches-the-daw-only-for-its-last-action.md) rule 5).
- Copy-on-write helpers are code the app owns where immer would have been a dependency; they cover the UI slices only, which are shallow.
- [ADR 0041](0041-host-bindings-read-project-services-through-one-snapshot-accessor.md) and [ADR 0069](0069-payloads-are-validated-with-zod-behind-parsewire-and-a-wrong-shape-fails-loudly.md) are kept unchanged: the store reads through the same bindings and the same `parseWire`.
- To hold domain state in the browser, or to take a state library, write a new ADR that supersedes this one.
