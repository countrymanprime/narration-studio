# 0864. A long recording is checked in overlapping chunks by parallel Whisper processes, and Whisper's word scores choose the passages a larger model looks at again

**Status:** Accepted
**Significance:** An interface between parts and a quality attribute: the recording check's sidecar gains worker processes, its words file gains a per-word score, and one function in the host now decides what a check runs for the dialog, a press and a background check alike. Undoing it means changing the words-file format, the cache key and every caller of that function.
**Date:** 2026-10-17
**Supersedes:** none. It amends [ADR 0841](0841-a-recording-check-lists-the-approved-whisper-models-as-its-engines-and-a-start-may-name-one-to-run-alone.md) (points 6 and 7) and reads [ADR 0830](0830-the-recording-check-names-its-gaps-missing-extra-or-misread-and-a-confidence-is-null-with-a-reason-until-words-are-scored.md) deliberately.

## Context

A chapter an hour long took about an hour to check: the sidecar made one Whisper decode of each item's whole played range on one model in one process. Transcript Compare already cuts audio into overlapping chunks and runs them in worker processes (`compare.transcribe_chunked`), but the recording check did not, and [ADR 0841](0841-a-recording-check-lists-the-approved-whisper-models-as-its-engines-and-a-start-may-name-one-to-run-alone.md) said so: "chunk length, overlap and parallel workers are not exposed".

Three other things were observed:

- The Check recordings dialog always sent `options.model`, and a named model runs alone (ADR 0841, point 6), so the dialog never ran the model cascade even with it on. A press from the Production slide-over used the cascade, and a background check ([ADR 0211](0211-a-changed-chapter-is-rechecked-in-the-background-only-on-mains-power-with-reaper-quiet-and-not-recording.md)) always used Transcript Compare's `model_size` and never the cascade. The same chapter was checked with a different model depending on where the narrator pressed.
- The cascade re-checks only what the first pass reports missing ([ADR 0344](0344-the-cascades-second-pass-is-a-relaunch-in-the-same-job-and-its-words-key-on-the-model-pair.md)). A first pass that hears a passage badly but matches the words by chance sees nothing wrong, so the larger model never looks at it.
- `WORDS_SCHEMA_VERSION`'s guard (ADR 0830) fails if the sidecar starts reading `word.probability`, so the change to read it has to be a decision.

**Considered options:** reuse `compare.transcribe_chunked` as it is (it drops each word's score, merges the crossover by matching text, and its first-chunk-in-process rule is right but its fixed 1.5 s overlap is not a choice); run whole items in threads (one Python process holds the model once per thread and the GIL is not the limit, but CTranslate2 threads share one model and gain little from more); score gaps from the word probabilities (no calibrated mapping exists, so a number would be made up, ADR 0830).

## Decision

1. **Chunks.** `sidecars/transcript-compare/core/coverage_chunks.py` cuts an item's played range into chunks of `chunk_seconds` that overlap by `chunk_overlap_seconds`, transcribes them in up to `parallel_workers` spawned processes and joins them. The cut between two chunks is the middle of their overlap; a word belongs to the chunk its midpoint falls in, so none repeats and none is lost. The first chunk runs alone in the sidecar's process: it loads the model before the workers race to read it and settles the language the others use when none was forced. `parallel_workers` 0 takes the model's own memory cap (`compare.MAX_WORKERS_BY_MODEL`); a named number is kept up to the computer's processors and the chunk count; a GPU runs one. Each worker gets its share of the processors as `cpu_threads`. An item no longer than a chunk goes to the plain transcriber, so a short recording is unchanged, with the same progress and cancel. Each chunk looks for the cancel file between its segments. Workers share chunks, so a whole item (chunk length 0) has one process.
2. **Scores.** A words file keeps Whisper's probability for each word as a fourth element (`[text, start, end, score]`). A reader still takes three, so `WORDS_SCHEMA_VERSION` stays 1; the host's words-cache version is raised to 3 so every chapter is transcribed again once and none shows no doubted passage only because it was checked before. A word with no score is never doubted: unknown stays unknown.
3. **Doubt.** With `--unsure-below <share>` the first pass writes a `COVERAGE_UNSURE` line for each passage of words scored under it (a run of at least two such words, or one under half the line, joined across up to two confident words). The planner (`internal/coverage/plan.go`) adds a window for each beside the windows of the missing regions, so the larger model looks at both. The lines are read, not stored: `Report.Unsure` is `json:"-"`.
4. **Gap confidence stays null.** The scores choose passages to look at again. They do not score a gap: no calibrated mapping exists, so a gap's `confidence` stays null with `no_word_scores`, now meaning "no score for this gap" ([ADR 0830](0830-the-recording-check-names-its-gaps-missing-extra-or-misread-and-a-confidence-is-null-with-a-reason-until-words-are-scored.md)). The guard test that failed on the word `probability` is replaced by one that pins the cache version.
5. **One resolver.** `apps/desktop/coverage_choices.go`'s `resolveCoverageChoices` decides what a check runs from the `RecordingCoverage` and Transcript Compare settings and the run's options: the first-pass model, whether and with which model a second pass follows, the doubt line, workers, chunk length and crossover. `CoverageStart`, `CoverageEngines` (its `default` and a new `defaults`) and the background check all call it. An option that is present and not valid is an error and nothing starts. A named `model` still runs alone unless the run says `recheck: "true"` ([ADR 0841](0841-a-recording-check-lists-the-approved-whisper-models-as-its-engines-and-a-start-may-name-one-to-run-alone.md) point 6, amended). A background check never downloads a model: a missing first-pass model leaves it waiting, a missing larger model leaves the first pass alone.
6. **Settings.** `RecordingCoverage.cascade_unsure_below` (0.5; 0 re-checks only what is missing), `parallel_workers` (0, chosen from the model), `chunk_seconds` (300; 0 is each item whole) and `chunk_overlap_seconds` (6). They change how fast the same words are made, not which ones count, so they are outside a result's parameter hash and changing one never makes a result stale.
7. **The dialog.** Check recordings shows the host's `defaults` and lets the narrator change them for the run: the model, whether a larger model looks again and which, the score under which it does, chunk length, parallel processes and crossover. It sends every choice, so the host runs what the dialog showed.

## Consequences

- A long chapter is checked in a fraction of the time on a computer with spare processors, at the cost of one copy of the model in memory per process; the model cap keeps `large-v3` to one.
- The first check after this change transcribes every chapter again (cache version 3).
- Chunk edges are the one place the transcript depends on the new setting: a word is whole in one of two chunks only if the crossover is longer than the word, which the dialog's smallest choice (2 s) is.
- Real-speech timing and accuracy of the chunked path are not measured here: the unit tests drive real spawned processes with a fake model, and no Whisper model was available. The shipped values (5 min, 6 s, 0.5) are provisional like the check's other numbers ([ADR 0132](0132-the-recording-check-ships-0-8-3-8-3-chosen-on-synthetic-fixtures-and-labelled-uncalibrated.md)).
- A word score as a gap confidence would need a calibration on real narration and a new ADR.
