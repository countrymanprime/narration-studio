# 0856. The Editing records are one file per kind, keyed by word with its text, checked on read and cleared when the manuscript is replaced

**Status:** Proposed
**Date:** 2026-10-11
**Supersedes:** none. It follows the sidecar pattern of [ADR 0382](0382-script-markup-is-a-chapter-keyed-sidecar-of-line-offsets-checked-on-read-and-drawn-without-changing-the-text.md) and [ADR 0820](0820-a-bookmark-is-a-spot-kept-in-a-project-sidecar-checked-on-read-and-cleared-when-the-manuscript-is-replaced.md), both Proposed; the rules it takes from them are restated below, so it does not depend on either being accepted.

## Context

The Studio Next Editing page shows a chapter's words with the recording's flags on them, and the narrator changes three things about those words that must outlive the session: words they keep as read ("It is right" on a misread, "Keep this addition" on words said and not written), words cut from the recording, and effects put on a range of words. The mock keeps all three in its data (`docs/research/mockups/studio-next/src/domain/schemas.ts`: `accepted`, `cuts`, `wordFx`) and names a word by `paragraphId:ordinal` (`src/selectors/scriptedit.ts`). Its `acceptWords` (`src/state/commands/scriptedit.ts`) records accepted words and Undo puts the flag back; an accepted word is neither flagged nor counted in the legend. The PRD (`studio-next-script-based-editing.prd.md`, "Contracts" and "Trust boundaries") names the cut and word-effect sidecars; it does not name the accepted words, which this decision adds because the legend counts and Undo need them.

Slice SNE-4 ([#1245](https://github.com/countrymanprime/narration-utils/issues/1245)) builds the accepted words; the cuts and the word effects follow it ([#1282](https://github.com/countrymanprime/narration-utils/issues/1282), [#1285](https://github.com/countrymanprime/narration-utils/issues/1285)). This decision fixes the format all three share before the first lands.

## Decision

1. **One file per kind.** The Editing records live in `<project>/narration-utils/editing/` (`editlog.Dir`, `apps/desktop/internal/editlog`), beside the per-chapter source choices already there: `accepted.json` (`editlog.AcceptedFile`), and later `cuts.json` and `wordfx.json`. Each is `{"schemaVersion": N, ...}` with its own version; `accepted.json` is version 1, `{"schemaVersion": 1, "words": [{chapterId, paragraphId, ordinal, text, acceptedAt}]}`.
2. **Narrator data.** Each file is read through `persist` as narrator data: a file that does not parse, or holds a record breaking a rule (an empty chapter, paragraph or text, a paragraph id with a colon, a negative ordinal, the same word twice), is kept aside as `<file>.corrupt-<time>` and an empty list starts; a file with a newer `schemaVersion` is refused and never overwritten. A write goes to a temporary file and is renamed into place. One package helper (`readVersioned`, `writeVersioned` in `editlog.go`) does this for every kind.
3. **The key.** A word is named by its chapter id and its key `paragraphId:ordinal`, the ordinal being its place among the paragraph's words split on whitespace as the UI splits them (`text.split(/\s+/).filter(Boolean)`), with the ordinal in plain decimal. The record also stores the word's text at the time. The bindings take a chapter id and keys, never a path: `EditingAcceptedList(chapterId)`, `EditingAccept(chapterId, keys)` and `EditingUnaccept(chapterId, keys)`. `EditingAccept` refuses, with a sentence and without saving any of the keys, a chapter the manuscript lacks, a paragraph not in that chapter, an ordinal past the paragraph's last word, a malformed key and an empty list. Accepting a word already accepted changes nothing; the answer's `changed` lists only the keys a call changed.
4. **The stale rule.** Every read checks each record against the current manuscript. A record whose paragraph is gone reads `stale` with `paragraph_missing`; one whose paragraph has fewer words reads `word_missing`; one whose word at the ordinal is not the stored text reads `text_changed`. A stale record keeps what it stored, is never moved to a neighbouring word or applied to a guess (the rule of ADR 0382), and does not count: a stale accepted word's flag shows again. Stale is never stored. A stale record can be removed; accepting the word now at that key replaces it.
5. **Reading order.** A chapter's records come back by line, then ordinal; a record whose line is gone goes last.
6. **Clearing on replace.** Replacing the manuscript (`ManuscriptImportCommit` with `confirmedReset`) and Clear project data remove the files (`resetDerived` in `apps/desktop/internal/manuscript/service.go` names each file, and already removes the folder). An import that resets nothing keeps them.
7. **Nothing reaches the DAW.** The records are the app's own: accepting, cutting or putting an effect on a word writes these files only, and clearing them deletes nothing from the DAW or the recording. What a cut or an effect does to the audio is the cut and effects slices' to decide.
8. **The wire.** `AcceptedWord`, `AcceptedWords`, `AcceptedWordsChange` and `EditLogApi` (`apps/ui/src/api/contracts/editLog.ts`), strict schemas in `apps/ui/src/api/schemas/editLog.ts`, the goldens `edit-accepted-*.json` written by `bindings_editlog_contract_test.go`, the `EditLogPort` (`apps/ui/src/ports/editLog.ts`), and host API 93.

## Consequences

- The Editing page's flag cards, Undo and legend read one host store through one port, and the browser mock answers the same shapes and refusals.
- An accepted word survives a re-import that keeps paragraph ids and the word, and its flag comes back when the word changed. Because the key is an ordinal, inserting a word before it makes it stale rather than following the word; carrying records across such an edit would need a new ADR.
- Words heard but not in the script (the mock's `paragraphId:xN` keys) have no ordinal in the manuscript, so this format cannot name them yet: "Keep this addition" needs a key for a heard word that survives a new alignment, which the alignment slices define.
- The schemas are strict, so a field added later needs a host API bump and a UI that reads it.
- Each file is read whole on every call (no size cap), as markup and bookmarks are; one call names at most 5,000 words.
- Clearing on replace loses every record of the old manuscript.
