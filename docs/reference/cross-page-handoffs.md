# Cross-page hand-offs

Every way one page sends the narrator to another, how the destination is addressed, and what the destination does with a bad address. Surveyed 2026-10-16 against `main` at `05f6233`; S13 and S17 re-read for the Delivery page. A page owner adds a row here when a page adds a seam ([checklist](../operations/page-owner-handoff-checklist.md)).

"Coverage" names the test that drives each side, as of the survey. **none** means no test drove it. The "today" cells describe `main` at the survey; [What the contract does](#what-the-contract-does) says what changed.

## What the contract does

**Addresses.** `apps/ui/src/navigation/address.ts` builds and reads every hand-off address (the Story Bible's Find in the manuscript and its `#<entity id>` reader use it; an entity id the Story Bible lacks shows a message with Dismiss and Go to Production in the list panel, `Guide.address.test.tsx`, matrix row S8). `addressPath(address)` never throws, whatever text it is given. `readAddress(page, location)` returns `address`, `none` (the address asks for nothing) or `bad` with a reason and a sentence for the narrator. The limits are `MAX_ADDRESS_TEXT` (512 characters per name), `MAX_PICKUPS` and `MAX_ADDRESS_NUMBER`. A value named twice, a number that is not a whole non-negative number, a drawer or credits kind the page lacks, a control character and a malformed percent escape are `bad`. The Booth's own shape (`docs/guides/using-the-app/booth.md`) is built by `boothQuery` and read by `readBoothQuery`, unchanged; the module wraps them.

**Bad and stale addresses.** `AddressGate` (`components/layout/AddressGate.tsx`) wraps the Script, Story Bible, Editing, Booth, Proof and Master & QC routes in `App.tsx`. A path no route owns shows `NotFoundPage` with a way out (S0 in the matrix). A `bad` read shows the message with **Open <page>** and **Go to Production**, both replacing the entry so Back does not return to it. The Booth fills the window and has no sidebar, so its message also answers the Booth's leave key (Escape, `booth.exit`) as it leaves a working Booth, replacing the entry: Pickups when the address still carries `pickups=` (the session `Open in Booth` opens, read leniently with `readPickupIds`, so a bad `pickups` list counts too), Script otherwise. A bad address keeps no record of the page the narrator came from, so the address's own pickup list is the only origin it can know; a link opened from anywhere else, or one that lost its `pickups`, falls back to Script, as a working Booth does. A named chapter, or a Booth line the named chapter does not list, that the chapter list lacks is checked by reading the list once more before the address is called stale; a failed re-read, no manuscript, or a list not yet read leaves the page to decide. The Script page says, once, when a `#c…` or `#p…` link names a chapter or line the manuscript lacks.

**Shared state.** The chapter list other pages show is the store's `chapters` slot (`docs/architecture/ui-state-and-journal.md#the-store-host-reads-cached`): stale on `job:ended`, on focus, and now on the in-app topic `MANUSCRIPT_CHANGED` (`studio/slots.ts`). A page that changes a chapter's status or kind outside a job calls `publish(MANUSCRIPT_CHANGED)`; Production does, through `onManuscriptChanged` in `App.tsx`. A topic reads the slot again, ignores a topic no slot lists, and drops an answer that arrives after a project switch. The pages that read `manuscriptChapters()` themselves (the list above) re-read on mount and are not told of a change while open; moving one onto the slot is that page owner's change.

**Tests.** `navigation/address.test.ts` (round trips and absurd addresses), `components/layout/AddressGate.test.tsx`, `studio/store/createStudioStore.test.ts` (`publish`), `src/crossPage.matrix.test.tsx` (the real `App` over the mock host, one row per arrival, bad address, reload and invalidation; it lists the seams it does not drive and why), `src/crossPage.proofPickups.test.tsx` (a Proof decision carried to Pickups and the rail on the mock host, and taken back) and `tests/visual/crossPage.spec.ts` (a real browser: history, reload, Escape, the click from Production to the Booth).

## Findings

- S1–S5: an unknown chapter in a Booth address rendered nothing. The gate now shows the message; `BoothNextPage` still returns `null` for it if reached another way, and belongs to the `fix/booth-resiliency` worker.
- S6, S8: a malformed percent escape in the hash threw `URIError` and showed the error boundary. The gate stops it before the page; `useDeepLink` no longer throws. `Guide.tsx` now reads the hash with `readAddress` (PR #1757).
- S6: an unknown chapter or paragraph in the hash did nothing and said nothing. It now says so.
- S6: Production's credits rows wrote `/script#ccredits-opening`, which names no chapter. `scriptPath` writes `/script#credits-opening`.
- S9: an unknown chapter in an Editing address opened the first chapter without saying so. The gate now shows the message.
- S14: the Booth sends `/settings#daw`, which `SETTINGS_ANCHORS` does not list. Not changed here: which category it should open is the Settings owner's call.
- T1: Booth, Editing and the other pages that call `manuscriptChapters()` directly do not use the slot.
- Found by the independent walkthrough and left to the page owners (details in the PR #1759 body): Script shows "Opening credits" as the current chapter after a hand-off to Chapter 1; Escape in the Booth goes to Script at Chapter 1; the jump menu pushes a duplicate history entry per chapter jump; `/proof/<unknown id>` renders an empty body.
