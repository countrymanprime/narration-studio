# Data files

The files the app writes and reads back for the narrator: where each one lives, what writes and reads it, where its shape is pinned, and how long it is kept. Use it to find what the app keeps in a project or a user profile, what to back up, and what is cleared when the manuscript is replaced.

`<app>`, `<data>`, `<executable>`, `<launcher folder>` and `<launcher script>` stand for values in `config/brand.json` ([Product and technical names](../architecture/codebase-map.md#product-and-technical-names)).

A file from outside the app (a manuscript, a REAPER or Audacity project, an archive, a downloaded file, an answered query file from an author) is not listed here; its row is in the [threat model](../architecture/threat-model.md).

Checked against the code on 2026-10-12 (`main` at `5bac319`). Paths in the tables are under `src/studio/desktop/` unless they start with a repo folder.

## How the app reads a file back

Every file on this page is written by the app and read back by the app for the same Windows user. Both ends run as that user, and there is no privilege boundary between two programs one person runs ([threat model, attackers](../architecture/threat-model.md#how-to-read-it)), so the file is inside the trust boundary.

On read, the host checks the file before using it: its shape, its version where it carries one, and the limits named in its row. Most files go through `persist.Reporter.ReadJSON` (`src/studio/desktop/internal/persist`, [Persisted files](../architecture/wire-contracts.md#persisted-files-srcstudiodesktopinternalpersist)); a few have their own reader. What happens to a file that does not decode, cannot be read, or carries a newer version than this app reads differs by file, so each row's Notes name one of these:

| Term | What happens |
| --- | --- |
| Kept aside | `persist.NarratorData`: the file is renamed to `<name>.corrupt-<timestamp>`, a fresh one is started, the host log records it and the narrator is told |
| Healed | `persist.Disposable`: the host log records it, the reader starts empty and the next save replaces the file |
| Refused | The binding returns an error and the file is left as it is |
| Read as absent | The reader starts empty without a log line, and the next save replaces the file |

A file that exists but cannot be opened at all (a sharing violation, a permission problem) is logged and left in place by `ReadJSON`. A writer that calls `persist.CanOverwrite` first then refuses to save; the rows say where a writer does not.

Every write is a temp file in the same folder renamed over the old one, unless the row says otherwise.

A hand edit of one of these files can change only the narrator's own data the app shows or judges by: a note, a mark, a status, a verdict. It must not make the app run a program, open or write a path, fetch a URL, or put markup into the page; a file that can is a vulnerability, reported as [SECURITY.md](../../SECURITY.md) says. The exception is a file whose job is to name a path the host opens, a command it runs or a URL it fetches: its row says so, and it also has its own row in the threat model, which bounds what the named target can do.

## Retention terms

| Term | Meaning |
| --- | --- |
| Cleared on replace | Removed by `resetDerived` (`src/studio/desktop/internal/manuscript/service.go`), which runs when the narrator confirms replacing an existing manuscript and on **Clear project data**. A first import, with no `manuscript.json` yet, clears nothing |
| Cleared on Clear | Removed only by **Clear project data** (`Service.Clear`), not by a replace |
| Kept | Nothing in the app deletes it |

The Windows uninstaller removes the program only and leaves every per-user folder in place (`src/studio/desktop/build/windows/installer/project.nsi`).

## Columns

| Column | Holds |
| --- | --- |
| File | The file name, linked to the code that owns it |
| Location | The path under the project folder or the per-user folder |
| Written by | The bindings or jobs that write it |
| Read by | The bindings or jobs that read it back |
| Schema or golden | The schema, golden payload or test that pins its shape |
| Retention | When it is created, replaced or cleared, and whether it is safe to delete |
| Notes | Limits, what is checked on read, and any departure from the read-back rules above |

No file has a JSON Schema of its own. A golden under `tests/fixtures/contracts/` pins the binding answer built from the file, which the UI checks with the Zod schema in `src/studio/ui/src/api/schemas/`; it pins the file's shape only where the row says "file". A unit test beside the code pins the rest.

- `<project>/<app>/analysis/coverage/runs/<run>/` and `analysis/coverage/credits-manuscript.json`: the recording check's hand-off to the sidecar and back (the manifest, the words files, the sidecar's `words-report.txt` and the host's `coverage.txt`), removed when the run ends.
- The take comparison's session folder (`takeReviewSessionDir`): the manifest, the sidecar's `take_divergence_words_<n>.txt` words report (removed when the run ends, [take_divergence_mode.py](../../src/studio/sidecars/transcript-compare/core/take_divergence_mode.py) for its lines) and the progress file; the host aligns the words and returns the results without writing them ([internal/takedivergence](../../src/studio/desktop/internal/takedivergence/results.go)).
- Transcript Compare's session folder: the sidecar's `words_<run>.txt` words report (its `COMPARE_SEGMENT` and `COMPARE_WORDS` lines, [compare.py](../../src/studio/sidecars/transcript-compare/core/compare.py)'s docstring; the chapter is the host's own choice, made before the run, so the report names none), the host's `results_<run>.txt` built from it ([internal/comparerun](../../src/studio/desktop/internal/comparerun/markers.go) for its lines, read by the REAPER bridge, the Audacity review and the findings adapter), and the run's `progress_<run>.txt` and `log_<run>.txt`. Nothing removes them.
- The pickup and duplicate scan's session folder (`takeReviewSessionDir`): its manifest, removed when the scan ends, and the sidecar's `repeats_<n>.txt`, a `REPEAT_WORDS` line of words per read ([compare.py](../../src/studio/sidecars/transcript-compare/core/compare.py)'s `find_repeated_spans`), removed once the host has read it ([internal/comparerun](../../src/studio/desktop/internal/comparerun/repeats.go) groups the reads; the findings are saved as `findings/take-review/<scope>.json`).
- `%TEMP%\<data>`: prompter, take-review and recorder hand-off files when no bridge session folder is given; most are removed when the run ends, and nothing prunes the folder.
- The REAPER bridge's `events.log` and exchange files live in the bridge session folder under REAPER's resource path ([threat model](../architecture/threat-model.md) row 5a).
