# Editing output audio

Design of the controls for the sound the Editing page plays, and a working sample of them (2026-10-21). The sample is built; the rows marked _not built_ below are a host contract, not code.

## What exists

- The bar at the foot of the script plays the chapter in the app, on one `Audio` element (`useScriptPlayback`), with the DAW closed ([Editing guide](../guides/using-the-app/editing.md)). A take audition on the same page (`useRangePlayer`) and a voice sample (`samplePlayerStore`) play on their own elements.
- Voice samples have an output device setting, `setSinkId` through `voicesamples/audioOutputs.ts`, kept per project in Settings. The Booth's Levels menu holds the DAW's monitor level (`useMonitorLevel`, the `monitor_level` capability: Experimental on REAPER, unsupported with the built-in recorder, [capabilities](../reference/daw/capabilities.md#monitor_level)).
- Editing had no volume, mute, speed or device control. The selection toolbar's **Mute** mutes _words_ in the recording, so the output mute is named **Silence output** and the two do not share a name.

## The controls

One group, **Output**, at the left of the bar after the clock, so the controls for hearing sit with Play: a **Silence output** toggle and an **Output** button that opens a popover. A speed other than 1× is written beside the buttons, so it is never a hidden setting. Nothing goes in the header and nothing is modal.

| Control                            | Where                                                                     | Does                                                                                                        | Works now                                                                  |
| ---------------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Speed (0.75×, 1×, 1.25×, 1.5×, 2×) | Output popover, a segmented group; written beside the buttons when not 1× | `playbackRate` with `preservesPitch`; `defaultPlaybackRate` is set too, because a new `src` resets the rate | Built-in player and take audition                                          |
| Silence output                     | Toggle on the bar (`aria-pressed`)                                        | `muted`                                                                                                     | Built-in player and take audition                                          |
| Volume                             | Output popover, slider 0 to 100 %                                         | `volume`; 100 % is the recording as it is, a media element cannot go louder                                 | Built-in player and take audition                                          |
| Output device                      | Output popover, select: System default, then the computer's named outputs | `setOutput` (`setSinkId`), kept by name                                                                     | Built-in player; take audition follows it                                  |
| DAW monitor level                  | Output popover, only with a DAW whose `monitor_level` is on               | `dawMonitorLevel` / `dawSetMonitorLevel`, the same hook as the Booth                                        | The DAW's own output when it plays; it does not change the built-in player |

The choices are one set for the page: the chapter and the take audition share them, so a muted page is quiet. They are kept in this window's storage (`narration-ui-editing-output`), as the take tone is, and are per computer: an output that exists on one machine is not a project fact. A voice sample keeps its own output setting and is not covered.

Keyboard: every control is a button, slider or select with an accessible name; Tab reaches them in bar order, the popover traps focus, Escape closes it and focus returns to the Output button. No new shortcut is bound (open question in the PR).

| Output refused or gone at apply time               | Alert "Could not play on <name>. Playing on the system default until it is back."; the element is put back on the default so audio is never lost   |

| Rapid changes                                      | Only the newest device choice reports; a change while playing does not pause or restart                                                            |
| Storage blocked or damaged                         | Defaults per field; choices hold for the window                                                                                                    |
| DAW off, no monitor capability                     | No monitor row. A row with the DAW's own sentence appears when the DAW answers a refusal                                                           |
| DAW not answering                                  | Level reads "…", then the DAW's sentence or "Could not read the monitor level: …"; the last confirmed level stays usable with the reason beside it |

## Not built

- **Loudness or peak readout of the output.** Needs the player routed through a Web Audio analyser; whether the media route allows it in the webview is unverified. The story draws the row as a labelled sample.
- **Playback through the DAW with its own volume and device.** The app does not start DAW playback ([daw-integration](../architecture/daw-integration.md)); the lit word only follows it. Needs a transport capability (`play`, `stop`) the repo does not have.
- **Output device of the DAW.** REAPER's device is its own preference; no capability reads or sets it. Needs a `output_device` capability and an adapter per engine ([daw-capabilities](../../.claude/skills/daw-capabilities/SKILL.md)).
- **Monitor on the built-in recorder, an input meter, per-track monitoring.** The Booth owns recording levels.
- **Keyboard shortcuts, and a mute that also silences voice samples.** Both need an owner decision.

## Host contract for the readout (not built)

If the owner wants the readout from the host rather than the webview, the host would push `playback_level` events `{ peak, rms }` in dBFS at about 10 per second while the app plays, from the same source file the player reads. That is a wire-contract change ([wire-contracts](../../.claude/rules/wire-contracts.md)) and a new event row; nothing here depends on it.

## Why not a menu for the speed

The `Menu` primitive fails axe (`aria-hidden-focus`) while it is open; `Menu.stories.tsx` closes it before axe runs for that reason. A segmented group in the popover needs no second overlay and keeps every output choice in one place.
